# 全剧资产提取与人物防漏

## 1. 读取策略

不要把一部剧本当成一个可以凭印象总结的短文本。先建立候选索引，再写清单。建议至少两遍：

### 第一遍：结构扫描

- 标出所有集标题、前情/片头/正片/下集预告边界。
- 标出所有场次头，保留原编号、地点、时间和内外。
- 收集显式人物列表、角色表和人物小传，但暂不以它们作为唯一来源。

### 第二遍：实体扫描

逐行检查人物、对白、动作、旁白、OS、回忆、梦境和场景说明。为每次命中记录：

```text
原文名称/称谓：
所在集/场：
上下文原句：
实体类型：人物/群体/动物/非人角色/道具/场景陈设/未知
出场类型：实际出镜/声音或画外/仅提及/无法确认
角色别名：
是否需要形象资产：生成/不生成/待确认
```

同一遍扫描还要建立服化道候选索引：角色的时代/地域/身份/职业/阶层、服装层次、妆发、配饰、随身物和每次状态变化的触发事件。

## 2. 人物候选来源（按覆盖优先级）

1. **显式角色表**：`人物：A、B、群众若干`、人物小传、集前角色表。
2. **对白说话人**：有台词但不在角色表的人必须加入；“掌柜：”“门卫甲：”这类角色标签也算。
3. **对白称呼与回应对象**：`妈`、`师父`、`经理`、`阿姨`等只有在语境指向一个具体角色时才合并；不确定时建候选并标待确认。
4. **动作行/场景说明**：`△ 老者推门`、`镜头外的护士敲门`、`回忆中的父亲`等都要留痕。
5. **旁白、OS、回忆、梦境和画外声音**：明确作为角色叙事功能出现的名字或身份全部记录。是否生成图像由出场类型和用户需求决定，但不能删除记录。
6. **群体与非人角色**：`众学生`、`三名护卫`按功能类型建群演资产；有名字的成员逐一列出。会说话、具有独立角色功能并需要出镜的动物/非人角色进入人物候选并标注类型。

纯粹泛指的人群（“人来人往”“路人”）可以归为群演/环境，不凭空创建个人姓名。反复出现的“老者”“店员”等无名角色，若无法证明是同一人，使用稳定的 `老者甲/老者乙` 或场次限定名，不能合并导致漏人或串人。

## 3. 别名归并

建立内部映射：

```text
定稿名：林晚
别名：林小姐、晚晚、摄影师（仅当语境明确指林晚）
出现集/场：第1集S01、第2集S04……
```

优先使用剧本正式人物表，其次使用全剧最稳定的正式称呼。官职、亲属称谓、昵称和代号只在明确指向同一人时归并。两个候选无法判定时保留两条 `[待确认]`，并在最终“待确认与依据”列出证据，不用“感觉像同一人”合并。

## 4. 出场类型与资产策略

| 类型 | 按集人物清单 | 人物总览 | 形象资产 |
|---|---|---|---|
| 实际出镜 | 列出 | 列出 | 生成 |
| 仅声音/画外 | 列出并标注 | 列出并标注 | 剧本/用户要求则生成，否则待定 |
| 仅提及 | 列出并注明原文 | 列出并注明集/场 | 默认不生成，但不得删除记录 |
| 无法确认 | 列出候选和上下文 | 列出待确认 | 暂不生成 |

这样既不漏人物，又不把“听说过的某人”误做成要出图的实际角色。软件若会为所有人物条目自动生成图像，必须读取 `不生成形象资产` 标记；无法支持标记时，把仅提及/待确认内容放在该集人物区的末尾，并在总览中保留审计注记。

## 服化道事件提取

在实体扫描中逐场记录换装、借衣、穿脱、制服/礼仪场合、发式变化、妆面变化、雨湿/汗污/泥污/血污、破损/修复、缺失配件，以及随身物和道具的交接、损坏、遗失、复原。每项变化都绑定触发它的剧本事件；没有触发依据就复用原状态，不为“好看”另建资产。

为每个需要生成形象资产的人物至少记录：

```text
时代/地域/身份/职业/阶层/场合：
服装状态：外层→中层→内层、面料、颜色、剪裁、鞋履、做旧：
妆发状态：发式、束发/冠帽、底妆、眉眼、唇颊、胡须/稳定伤痕：
配饰/随身物：
识别点与场景色彩关系：
状态触发与下一场入口：
```

这些字段服务静态资产和连续性账本；人物表中不得因此加入表情、动作、视线或对白。

## 5. 场景提取

场景以场次头为准，建议保存原文和规范 ID 两列：


```text
原文：1-3 暖厅外廊 黄昏 内
规范 ID：
地点：暖厅外廊
时间：黄昏
内外：内
首次出现：第1集
```

同一地点不同时间、季节或内外是否拆成不同资产，按项目规定；没有规定时，至少在场景条目中写清时间状态，避免白天/夜晚光线混用。场景说明中出现的人不改变场景 ID。

## 6. 道具提取

道具来源：

- 动作行中被拿、放、开、关、穿戴、佩戴、交接、损坏或使用的实物；
- 台词明确点名且可能需要画面资产的物件；
- 人物随身的武器、法器、手机、相机、包、证件、首饰等；
- 需要读清的书信、屏幕、招牌、票据和徽章；
- 对剧情有独特身份/能力/线索作用的物件。

固定墙、地板、门窗、柜台、床和大部分背景家具归场景陈设，但仍在内部候选表记一笔“已识别、无需独立资产”。如果固定物件会被人物操作、成为线索或需要单体图，则升级为独立道具。

不要从抽象名词创建道具（“爱情”“命运”“过去”），不要把同一把刀在不同镜头写成两把刀。道具只因本体、文字、开合、损坏、魔气/灵光或所有权发生可见变化时建状态变体。

## 7. 零漏核对矩阵

写完前用下面的交叉核对，内部完成即可：

```text
角色候选总数：____
按集人物条目去重后：____
人物总览条目：____
仅提及/待确认条目：____
所有对白说话人是否命中：是/否
所有动作行具名人物是否命中：是/否
所有场次头是否命中场景：是/否
所有道具候选是否已建资产或记为陈设：是/否
```

计数不一致时回到原文查找；不要为了让数字相等而删除条目或凭空增加人物。
