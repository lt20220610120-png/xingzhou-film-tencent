# 美术资产命名、复用与软件层级

## 1. 稳定 ID

资产名是软件识别 ID，全篇逐字一致。名称简短、具体、可搜索；不要在同一个项目中一会儿用“便服”、一会儿用“日常装”指同一件衣服。

| 类别 | 推荐格式 | 示例 |
|---|---|---|
| 人物基准形象 | `【角色名-基础形象】` | `【姜蓝-基础形象】` |
| 人物造型 | `【角色名-具体服装状态】` | `【姜蓝-蓝色剑道服】` |
| 人物伤病/身份状态 | `【角色名-具体状态】` | `【姜蓝-病号服】`、`【姜蓝-囚服】` |
| 人物妆发状态（仅需独立资产时） | `【角色名-妆发状态】` | `【姜蓝-礼仪妆发】` |
| 群演 | `【群演类型-服装状态】` | `【家丁-青布短褂】` |
| 场景 | `【地点-时间-内/外】` | `【南家大厅-日-内】` |
| 道具 | `【道具名-状态】` | `【婚书-完整】`、`【婚书-撕裂】` |

角色名、地点名和道具名优先沿用剧本定稿名。人物 ID 可以有服装状态，但人物总览必须先有角色总条目，再在下方列状态子资产。仅提及人物可用 `【角色名-仅提及】`，并在同一条写“不生成形象资产”；不把它混入实际出镜的造型 ID。

## 2. 首次、复用与状态变体

### 首次出现

第一次出现该资产形态时写完整描述，并标 `（首次：第N集/场次）`。完整描述应该包含软件生成该资产所需的事实，不靠模型猜测。

### 复用

后续集仍是同一形态时，按集清单列 ID 并标 `（复用自第N集）`，不重复长描述。换机位、换景别、换手、自然褶皱和角色姿态不构成新资产。

### 新状态

以下情况通常另立资产，并指向原资产：

- 剧本明确换装、借衣、穿脱或身份伪装；
- 伤病、囚禁、婚礼、战损、雨湿、血污、泥污、撕裂、烧焦、妆脱、发式散开；
- 道具开合、破损、文字、所有权或超自然状态发生可见改变。

新状态只写差异，不复制没有变化的人物脸型、五官和静态气质。若只是心情变化、镜头变化或小幅自然褶皱，复用原 ID。

## 3. 三类平级结构

按集必须严格使用：

```text
### 第N集
人物：
- ……
场景：
- ……
道具：
- ……
```

三个类别是平级标题，资产条目只归属于对应类别。总览直接使用：

```text
## 人物总览
## 场景总览
## 道具总览
```

不得在 `人物：` 下嵌套场景/道具，也不得用表格把软件需要解析的条目藏在类别标题旁。人物状态可以作为人物条目下的二级列表；场景与道具总览保持扁平。

## 4. 名称一致性回读

写完后按 ID 逐字比较：

- 每集清单出现的 ID 是否都在对应总览出现一次？
- 总览的每个 ID 是否都能回指至少一个集/场？
- 同一角色的所有状态 ID 是否共享同一个角色名？
- 复用条目是否误写成新资产？
- 状态变体是否保留原资产关系和首次出现位置？
- 服装与妆发是否无依据拆成过多资产；需要独立生成时妆发 ID 是否稳定并能回指人物基线？
- `仅提及/不生成形象资产` 是否被误标为实际出镜？
