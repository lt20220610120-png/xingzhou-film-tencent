# 2.8.198 发布验收

2026-11-23，Windows 凭据迁移与激活页登录紧急修复。

## 故障与恢复

- 2.8.194 的 Electron 在历史目录初始化 Chromium 密钥，随后把应用数据目录设为新名称。2.8.195 提前设置 `userData` 和 `sessionData`，Chromium 从新目录读取了另一把密钥。升级后，2.8.197 无法用新密钥解开保存在现有目录里的旧密文。激活页也缺少返回既有账号登录的入口。
- Windows 下用同一用户的 DPAPI 打开原目录的 Chromium 密钥，验证旧密文及数据结构后，通过当前 Electron `safeStorage` 重加密。校验当前密钥读回相同内容后才替换对应文件。两个目录的 `Local State` 均保留原样。无法确认来源或完整性的密文原样保留。
- 本机先保存原会话、设备密文和 Chromium 状态的额外检查点。恢复后，云端状态为原账号已验证且免卡，2.8.197 实机打开工作台和管理后台。导演项目 81 条、剧本项目 4 条、创作项目 6 条、对话接口 22 条、媒体接口 31 条与升级前备份逐项一致。完整资料备份保留原样。
- 激活页的「已有账号登录」共用原密码登录与找回流程。云端保留账号、设备、月卡及管理权限判定。工作台要求云端确认账号已登录且授权生效。

## 隔离验收

- 从 2.8.194 和 2.8.197 正式 NSIS 中读取原始代码，通过真实 Windows Electron 重现旧版的目录初始化和加密。2.8.194 能写入；2.8.197 对同一套会话、设备、记住的卡密、Like 与 LibTV 凭据均读取失败，五份密文原样保留。
- 2.8.198 正式 NSIS 载荷原样启动，隔离环境禁止云端访问。退出后独立 Electron 确认五份凭据全部能用当前系统密钥读取，且设备公钥保持一致。旧、新 Chromium 密钥均原样保留。模拟鉴权服务仅留在源码测试夹具中，正式包不包含该服务。
- 隔离 Electron 连接模拟鉴权服务，旧会话自动进入工作台，使用原 Ed25519 设备身份完成签名验证，无二次登录。空白资料目录正常登录写入，重启后自动读回。独立界面测试验证无有效月卡拦截、免卡通过、网络错误重试、登录返回焦点与既有卡密注册。
- 全量 Node 测试 3,235 项、发布 Python 测试 13 项、本地 Qwen 12 项，Vite 构建和正式打包运行时通过。多宽度界面覆盖 1280、1600、1920，测试无外部字体请求。正式包验证 COS 本地缓存、临时参考图与中转回退、Like、LibTV、WorkBuddy、Win AI、画布和历史项目读取。验证中付费调用为零。
- 本次发布改动位于桌面程序、测试与发布记录，沿用既有云端授权。未部署或重启生产服务。
