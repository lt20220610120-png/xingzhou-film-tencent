# 2.8.200 发布验收

2026-11-23，LibTV 本机代理适配、连接诊断与分镜预检反馈。基线为 2.8.199 和 `5f876d1`。

## 根因和改动

- 旧版按 60 秒时效重新并发探测四个官方主机，建立 TLS 后立即拆连接，只解析 HTTP/HTTPS 系统代理。新版选路发生在 CLI 实际请求时，按目标缓存，复用成功路径。系统代理支持 HTTP、HTTPS、SOCKS4 和 SOCKS5，支持本机直连和自定义代理。
- LibTV 本机网络设置使用独立配置。自定义地址拒绝内嵌账号、密码和路径。账号、模型与节点查询安全退避，参考上传沿用有限次数重试。已启动的付费运行仅提交一次，断线后依靠已保存的原节点恢复查询。
- 设置页通过账号与模型列表实查验证连接。输出阶段、路径、错误码与建议，诊断文本不包含代理地址、账号名、Cookie 或凭据。
- 准备和预检在内存中追踪。手动生成通过操作区提示原因，批量队列保留每条失败原因。画布待生成或 付费指令交接时才写结果记录，已提交任务和历史记录可正常查看。

## 隔离验收

- Windows Electron 43.2.0 原生 Chromium 代理解析与本机测试代理覆盖直连、系统 HTTP、系统 SOCKS5、自定义 SOCKS5。本地测试包含短暂断线、超时、响应分片、备用通道、目标域名边界、取消和付费单发。
- 三宽 LibTV 设置检查通过，可切模式与校验地址，展示账号和模型阶段异常，复制脱敏诊断，取消和关闭后丢弃迟到回包。
- Node 全量 3,262 项，发布 Python 13 项、本地 Qwen 12 项和 Vite 构建通过。测试采用隔离数据与模拟上游，真实付费调用为零，无云端业务部署。


- 分镜实机验收涵盖 1280、1600、1920px。模拟账号 TLS 超时、参考音频连接重置后，错误显示在操作区，新增前置失败卡片 0 张。旧失败卡保留，模拟付费发送后失败新增 1 张，模拟付费运行指令 1 次。批量队列在刷新和重启后仍保留具体准备失败原因。
- 冷启动连接器下载使用所选网络模式，连接测试取消能中止下载。最终 NSIS 中 9 个关键模块与冻结源码逐字节一致。真实 Windows Electron 复核 2.8.194 旧凭据写入、2.8.197 跨加密目录读失败、新版读回和新会话重启。2.8.199 分镜保位与定向定位回归通过。
- 源码 `71322bc`，安装包 95,241,365 字节，SHA-256 `b5efd80df726f33e76a4648a2c59a6dab225ada14f797ce169ee99a21f5682e5`。GitHub Release 455106129，三份签名更新清单核验通过。官网范围请求返回 HTTP 206 并匹配本地安装包。本机与官网镜像保留 2.8.196–2.8.200 五版。
- 2.8.199 正式包的更新界面与更新模块在隔离 Electron 中检测到 2.8.200。模拟中断后走官网续传，并通过安装器交接前的签名、大小与摘要校验。2.8.200 正式载荷另行在隔离目录启动。
