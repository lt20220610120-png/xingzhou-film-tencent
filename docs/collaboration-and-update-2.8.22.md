# 2.8.22 多人协作与更新下载

用户要求共享剧本像协作文档一样：邀请成员后，每人可修改，其他成员能看到。原来的整本本地副本、手动上传流程不足以满足这一要求。

## 根因与选择

本机只读检查发现应用状态文件约 96.5 MB，其中导演项目约 59 MB。输入后的全局保存同时在渲染端序列化整个状态，在主进程同步写盘；协作版本弹窗又一次渲染整本约 8.7 万字，加上全屏模糊，多个成本叠加。不能用增加上传次数来解决。

已检索并比较主项目及官方文档：

| 项目 | 优点 | 对行舟影视的选择 |
| --- | --- | --- |
| [Yjs](https://github.com/yjs/yjs) / [更新协议](https://docs.yjs.dev/api/document-updates) | MIT；文字及独立记录的增量合并、幂等和状态向量 | 采用核心库，保留现有编辑器及剧本模型 |
| [Hocuspocus](https://github.com/ueberdosis/hocuspocus) / [服务端文档](https://tiptap.dev/docs/hocuspocus/server/hooks) | Yjs 的 WebSocket、鉴权和持久化服务 | 当前 v4 要求 Node 22，现有云端 Node 18；此版使用现有鉴权 HTTPS 服务，避免同时改服务运行环境 |
| [Automerge Repo](https://github.com/automerge/automerge-repo) / [官方介绍](https://automerge.org/blog/automerge-repo/) | 文档仓库、离线数据及同步能力完整 | 参考离线优先设计；直接替换仓库会扩大已有项目模型迁移范围 |
| [ShareDB](https://github.com/share/sharedb) | 成熟 OT 文档协作服务 | 可行替代，但需要另一套转换及传输服务，此版没有同时引入 |

结论是采用 Yjs 增量核心与现有云服务结合。不是引入另一款完整文档软件；没有宣称上述任何项目能直接替换全部行舟流程。

## 最终行为及兼容边界

- 活跃共享项目约每秒交换一次文字/字段增量，通常约 1–2 秒可见；这是 HTTPS 增量同步，不是 WebSocket，也不承诺网络异常下即时可见。
- 同一文本用 Y.Text 合并，集、提示词等带 ID 的数组按独立记录合并。保留现有字号、编辑器、人工划分与生成流程。并发合并解决数据覆盖，不自动判定两种剧情哪个更好。
- 本地 CRDT 检查点按账号、数据目录、项目隔离。断线保留未确认增量；重连幂等重试。中文输入法组词期间不强行替换正在输入的内容。
- 云端每次验证当前成员资格、锁定、回收状态；与旧版发布、恢复共用项目行锁。制片恢复会产生广播增量；普通成员无权恢复共享历史。
- 每个已接受增量保存作者及幂等 ID。完整历史检查点在有变化时约每 5 分钟保存一次，并提供手动检查点。旧版完整上传、冲突版本继续保留。取回旧的本地版本时另建独立本地副本，防止自动同步意外改变共享项目。
- 旧版未上传草稿与共享数据同时修改时先保留、确认迁移，不默默覆盖。跨账号或切换目录的旧请求不能写进新目录。
- 历史剧本每页最多 6000 字，保留全部内容。全局 JSON 序列化与落盘交给后台保存线程，退出先等待保存，网页服务的关闭超时不会截断保存。
- CRDT 历史随编辑增长；此版未做破坏性压缩。超大单本剧本的首次加载及本地结构化克隆仍有成本，不能将本轮 8 万字测试外推成无限规模性能保证。

## 更新下载

新增 `/api/updates/latest.json` 与受限安装包下载路由，支持 HTTP Range、流式传输。官方 IP 备用连接继续校验已有 CA 和固定证书；域名/GitHub 线路使用桌面系统代理。只允许固定官方路径及 GitHub 发布地址，不接受任意远程安装文件。

发布脚本先核验安装包与签名清单，再上传相同安装包至官方服务器，原子切换清单，然后同步两个 GitHub 更新清单。下载采用哈希绑定的部分文件，网络中断后续传；断点不合法、大小或哈希异常时丢弃无效部分。安装前校验 Ed25519 签名、大小、SHA256 与 Windows 文件头。此版本改善新客户端的下载能力；旧客户端若仍下载失败，需要先用公开安装包升级一次。

## 验证

- 浏览器三个独立成员窗口：41 集、82965 字初稿完整保留；多人同时编辑总稿、场景文字和删除可互见，断线编辑重连合并；恢复版本分页可读。
- 此组浏览器验收后续同步请求约 77 字节（空闲）或 419 字节（示例文字改动），不是每次传整本项目。最终重测最近 200 帧最大间隔约 16.6 ms；这是开发环境的限定样本。
- 五成员真实 PostgreSQL 临时表/回滚测试：相同字段首次并发编辑、独立提示词、删除、重试、检查点、旧版历史恢复、成员撤销、锁定与回收验证。
- 最终全量 1934 项测试通过，构建通过。三个实际 App 窗口另验证：保存失败会拒绝退出提交、可重试；私人历史取回不改变共享剧本，预览字号及黑色样式正常。本轮没有调用付费模型，也没有改写用户现有剧本作验收。
- 实际打包运行通过：DOCX、创作资料、模拟项目、本地回收、素材、账号网页接口、嵌入画布及沙箱检查正常。安装包 103552233 字节，SHA256 `7e619c6fd89c1cbde7ebc0c371d18af71dd9651a3abd6702023652c715f50eaf`。
- 云端增量部署完成；五成员实时协作、五成员旧版版本管理、三日云回收的 PostgreSQL 验收全部通过并回滚临时数据，云服务及定期回收服务正常运行。
- 独立最终复核通过，另运行 20 项实时协作、退出与更新专项测试全部通过；实际关闭监听先保留窗口，只有前端与后台保存成功后才允许关闭。

## 发布与下载验收

- 源码提交 `ba9577f` 已推送；[2.8.22 发布页](https://github.com/lt20220610120-png/xingzhou-film-updates/releases/tag/v2.8.22)公开可用，两个 GitHub `latest.json` 一致，发布签名与本地清单一致。
- 从 GitHub 公开链接完整下载 103552233 字节，SHA256 与本地安装包及签名清单一致。
- 使用与软件相同的官方 IP 证书验证及下载函数：先取 65536 字节，再从 `Range: bytes=65536-` 下载余下全部内容，最终文件大小和 SHA256 全部一致。该实测持续数分钟，超过旧版 120 秒整体期限仍正常完成。
- 本机域名路线经环境代理测试发生 TLS EOF；此次没有声称该路线在所有网络可用。软件优先使用已实测的固定证书 IP 路线，并保留域名和 GitHub 备选；用户公开下载链接采用已验收的 GitHub 地址。
