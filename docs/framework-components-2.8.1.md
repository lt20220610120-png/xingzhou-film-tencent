# 组件式框架创作 2.8.1

2026-10-08，根据用户对 2.8.0 的流程和截图反馈整改。示例仅用于隔离验证，不写入用户正式故事资料。

## 流程区别与实现

旧界面把大事件、小事件和可选中事件混在事件骨架板中；主线确认依赖小事件和衔接，不能在尚未展开小事件时确认大事件顺序。新界面拆为大事件收集、主线排序、小事件展开三个页面，增加独立的 `mainline.orderConfirmed`。完整故事确认仍在小事件的衔接页，之后才能生成正式集纲。

左侧固定顺序：总剧本、对标剧本；灵感、设定、大事件、主线、小事件、集纲、正文；辅助的人物、模拟、历史。

大事件收集不显示 ABC 序号。主线给大事件编号，移动后自动更新小事件的展示编号，稳定 ID、分集引用和历史保留。可选中事件保留在旧数据中，默认创作界面不要求新增这一层。小事件能跨大事件移动，旧额外衔接完整显示并可复核或移除。

模拟区有 `layer=groups` 和 `layer=group` 两种范围，读取全剧上下文。局部模拟只能改变当前大事件的小事件，不能改其他大事件、目标或全剧大事件顺序。大事件重排保留已有内部小事件。向后推理保留指定起点之前的前缀，固定节点约束与旧候选过期校验继续有效。先存为候选版本，再人工采用。

总剧本汇总全部故事、当前集纲、当前版正文。正文编辑更新所属版本和对应分集，导出可选故事稿、集纲或分场正文。正式收录仍要求正文完成与终稿复核。集数可以留空，模型按故事合理分集；手动建版填写集数。

## 视觉和本地编辑

大事件卡片固定 284px，主线卡片固定 320px，正文在卡片内滚动。小事件使用左右目录和编辑区，两侧独立滚动。导航 15—16px，正文 16px，深色正文；中文字体使用微软雅黑、苹方回退。界面无大事件编辑遮罩，不显示无必要的实际时间字段。

框架字段轻量本地暂存，每次输入写独立草稿，不依赖失焦；350ms 提交、连续输入每秒提交一次，中文组字期间暂缓提交，失焦或切换页提交。待定设定和过期集纲也允许保存手写草稿，正式生成、采用和终稿确认继续执行依赖检查。草稿恢复比对原值，防止覆盖随后产生的新稿。

全应用本地文件保存保持 250ms 合并，并增加持续输入最大 1 秒间隔及离页/隐藏窗口刷新。共用保存覆盖洗稿和内容创作。没有新增自动云端稿件写入。
