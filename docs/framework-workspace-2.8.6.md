# 框架式创作 2.8.6 验收

已发布：[行舟影视 2.8.6](https://github.com/lt20220610120-png/xingzhou-film-updates/releases/tag/v2.8.6)。在软件内“设置 → 检查更新”获取安装包。

## 本次行为

- 大事件分组按钮用自适应等宽网格铺满小事件页的横向空间，保持统一高度和间距。
- 整段划分、整理及分析浮窗的底部接口标签、选择框、操作按钮横向对齐，操作栏固定，标题栏可拖动。
- 整理事件前可填写要求或使用默认整理。默认围绕本作主角，按明确对应关系适配主角姓名，其余来源人物使用关系称谓；不能确定的对应关系交由用户核对。模型输出仍是候选，不直接改稿。
- 候选可按补充要求再次整理，带上前一候选和既往要求链；当前要求优先，未被明确改变的人物映射等要求继续保留。
- 主线 A、B、C 是位置编号。页面标明当前顺序是否确认，进入页面不调用 Agent。大事件内容与顺序的人工确认保持独立。
- 全部/当前大事件小事件分析读取全剧灵感、确认设定、所有大事件及已确认顺序，数量由故事决定，生成具体行动与跨事件衔接候选。
- 分析采用保留已有正文、ID、归属和顺序，只补全未确认空白草稿或插入新事件。固定大事件跳过改写，固定小事件不可挤动；原有中事件保留，不要求重复生成直接小事件。候选预览包含时间、前提、结果、动机和伏笔，明确清空的字段不会错误显示为保留。
- 创作区保持顶部工具栏，限制外层溢出；长事件仍在等高卡片内编辑和滚动。

## 验证

- 测试先行：新增分析测试在功能实现前失败；独立复核发现的中事件兼容及续改要求链分别加入回归验证。
- 最终 `npm test`：**1760 项通过、0 失败**；生产构建通过。构建仍有既有的大文件体积提示，不影响构建完成。
- 浏览器使用真实 React 工作区、`useCreatorAgent`、任务上下文和候选采用逻辑，仅把外部 `aiChat` 换为模拟接口，未调用付费模型。
- 2048、1440、1120 宽度下分组按钮首行右侧余量均为 0，等宽差小于 1 像素，无横向页面溢出。2048 宽度下 13 个分组每行 6 列。
- 进入主线和打开整理要求窗都没有调用模型；自定义要求和所选接口实际传入任务；默认整理、候选续改、全部分析、当前组分析、采用前原稿不变及采用后旧卡片保留均通过。
- 中事件保留、错误/重复/遗漏/跨父节点引用、固定卡片位置、过期候选及空白草稿稳定编号都有定向测试。候选动机/伏笔预览和明确清空字段另经浏览器验证。
- 长卡片场景外层页面及保留工作区均无额外滚动，内部滚动至最后内容后底部约 38 像素，为常规间距；顶部工具栏位置不随内容滚动。
- 整段划分窗口拖动位移验证为横向 -50、纵向 +35 像素；底栏选择器与按钮中心误差小于 1 像素。
- Windows 实际打包运行验证通过，包括稿件导入导出、DOCX 往返、本地媒体、内嵌画布、会话加密、IPC 未登录拦截、CSP、沙箱和生产调试入口关闭。现有 2.8.4 安全保护保留。
