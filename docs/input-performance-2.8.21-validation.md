# 输入与保存性能 / 2.8.21

日期：2026-10-10。

问题路径：App 的整套状态缓存序列化与 IPC 保存有 250ms 停顿、1 秒最长间隔；FormattedEditor 每字转换整个 DOM 并更新项目，部分项目更新还会归一化历史资料。框架 Field 虽有本地草稿，仍会在 250ms 后同步写缓存；图视生成、分镜草稿直接逐字写 localStorage。

实现：项目正文编辑区采用 1.2 秒停顿合并提交，15 秒最长检查点，输入期间避免逐字转换 DOM 与更新整个项目；按分集、场景和编辑侧区分缓冲。框架草稿和图视/分镜缓存合并保存。全局写盘调整为停顿保存和最长检查点，中文输入法组合期间暂停提交。操作前、失焦、手动保存和页面离开保持提交路径。

独立复核发现并修复了 IME 恰好覆盖全局 deadline 时不再创建后续 deadline 的边界；真实 App 保存逻辑在假时钟下持续输入至 46 秒，检查点恢复验证通过。

实际 App + 模拟接口：60 集及历史资料测试项目，框架灵感和自由总稿连续打字过程中缓存写入、saveState 调用均为 0；操作前即时采用灵感、中文选词期间不保存半成品、手动保存最终中文、连续编辑光标保持、快速切集保留末尾内容且没有跨集覆盖、写盘失败后原文保留并可重试均通过。未触碰用户真实项目或调用付费模型。

验证日志：output/playwright/edit-buffer-2821-*。最终全量检查、独立复核、安装包和公开发布信息在完成后补充。

最终全量测试：1,924 项通过、0 失败（13 suites）；Vite 构建通过。独立复核完成。最新版输入 UI 再跑通过：连续输入缓存与 saveState 写入均为 0，IME、手动保存、切集和失败重试保持正确。
