# 2.7.2 创作者续写与分场验证

## 修复依据

2.7.1 的正文审稿接口要求返回包含完整正文的 JSON，正文里的换行、引号和长输出容易造成解析失败。初稿与修订稿均直接加入正文版本，失败重试又重新转写。连续队列还将全部审稿提醒视为阻断条件。

2.7.2 分离干净正文和短 JSON 对照卡。自动修订输出纯正文，过程保存在输入指纹绑定的任务检查点，最终稿才加入版本列表。输出截断自动接续，审稿结构最多修复两次，临时网络错误最多重试两次。接口仍失败时保存进度，后续同输入继续；结构始终无效的审稿明确标为人工核查提醒，不能声称审稿通过。

已采用内容和历史来源各自保存；删除历史不清空当前成果。生成期间输入变化仍保留候选，禁止覆盖手动编辑。修改、来源更新和重新规划会使后续稿待复核。

## 真实模型测试

- 使用用户授权的接入模型 `cn:deepseek-v4.1-flash` 和实际导入的小说，源文本 253,576 字符，100 个目录章节。
- 隔离复制现有 43 集规划，从空正文依次转写；没有写入用户实际数据文件。规划的选材终点继续使用用户现有方案，没有将所有小说章节强制搬进正文。
- 43 集全部生成，正文按软件口径统计 121,173 个非空白字符（不含设定与集标题）。各集均识别场景编号，每集只新增 1 个最终正文版本；原文对照与人工核查提醒独立保留。
- 共 111 次实际 API 调用。第 7 集后测试脚本对总稿包含完整集标题的断言不适用于现有导出规则，修正测试断言后从已保存结果继续；不是模型或转写流程失败，已完成分集没有再次转写。
- 此验证证明调用流程完成与版本保存行为，不证明模型对照内容全部准确，也不证明字数对应 60 分钟成片。终稿人工确认仍由用户完成。

## 回归与界面

- 新增回归覆盖：不规范 JSON 自动修复、旧版初稿继续核对、网络失败后复用初稿、正文截断自动接续、待核提醒不阻断、自动修正只留最终正文版本、同任务去重、部分章节定位、跨章定位与可逆空白匹配、CRLF 场景编辑、删除历史保留已采用成果。
- 浏览器验证了 1-1/1-2 场景切换、仅编辑当前场、总稿同步、实际章节范围标题、连续队列单版本、人工确认不被自动代替、规划窗口顶部固定和上下两组操作、历史与聊天删除，以及 1600/1180 像素布局。
- 不使用真实接口做浏览器模拟测试。用户项目、API 密钥和实际生成文本不进入 Git。

## 发布验证

发布前执行全量测试、生产构建及安装包运行时验证；发布后核对安装包公开下载、两处更新清单、文件大小和 SHA256。最终数据记录在发布确认提交中。
