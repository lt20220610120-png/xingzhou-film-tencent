# 2.8.120 验收（2026-11-03）

基线 `6e91e75`。本版目标是把制作聊天还原成接近 Codex 的持续协作会话，同时保留行舟自己的固定身份、默认制作流程和自动调度语义。

## 行为修正

- 开工时选择的是初始 Agent 模型；开工后输入框仍可切换模型和推理强度。切换会在下一条消息生效，继续使用同一 Codex 对话线程，不会重启项目、丢失上下文或暂停自动流程。
- 用户聊天是更高优先级的临时调整。默认 `after=resume_default`：例如先做第一集并完成归档、超分、剪辑后，自动解除临时范围，继续全剧默认流程。
- 只有用户明确点击暂停或明确要求完成后暂停，自动流程才停止；聊天回合结束、流式回复结束或单集临时安排完成都不再被解释为全流程结束。
- 制作队列只在实际执行器存在且运行时显示“正在运行”；区分后台生成/下载、等待自动接续、调度未接续、暂停、等待充值和完成。自动流程累计用时与单次聊天回合用时分开显示。
- 交互制作会话使用 `danger-full-access`、`approvalPolicy=never`，创建线程和每轮运行保持一致；后台结构化子任务仍使用原受限权限。会话支持图片原生输入，视频与普通文件传递真实本机路径。

## 参考与边界

OpenFilm 的定向 REA 证据只分析了 `src/agents.mjs`、`src/chat-ipc.mjs`、`src/chat-store.mjs` 三个模块；事实仅为 ACP 会话、持续 update、附件路径/字节 IPC 和前端 full-access 偏好。该静态分析不证明运行权限，也不是完整逆向。行舟没有照搬 OpenFilm“指令完成后停止”的产品语义。

未修改用户真实制作数据，未替换正在运行的客户端，未执行真实付费视频生成；Topaz 增强、OpenFilm 成片与真实上游视频生成仍需用户项目实跑验收。
