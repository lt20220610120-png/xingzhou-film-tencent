## 实现与数据边界

- directorPromptCoverage 复用到制作流程与导演分集栏。按真实场景、人工分段或活动自动计划核对保存内容、身份、完整标记、重复编号及原文/设定变化；不使用 episode.status 作为完成证据。
- promptBindingVersions 区分保留原身份、正文和已知模型的增量补缺与真正替换。补缺版本投影为一组，保留原始存档；已确认关联按逐条来源证据复用。新旧原文、被引用卡身份、人工草稿等变化仍使旧结果失效。
- 旧版补缺分叉在读时合并查看、按条恢复已有分发结果；保存保留原 versions 数据和手工决定。不同模型、删除或替换提示词仍保留不同版本。
- 刷新仅接续本会话已经启动的信息读取/分发任务，不因打开页面或停止后的刷新发起模型请求。刷新遇到进行中的分集任务会排队复扫，补缺不再使原任务失效；真正替换仍拒绝过期回包。手动启动补齐缺少的场景和提示词关联，保留 CAS、人工编辑保护和独立停止。
- “核实分发”全剧版本选择保存在当前账号/项目的本机导航中；所有分集、场景及提示词统一选择。该选择是核实查看范围，不改写导演源或他人的项目内容。
- 重复的场景/分发启动入口合并，分层保留场景清单与逐条提示词两种检查视图；人工核实、发布及重新关联独立保留。
- episodeVoiceRoster 按 speakingSceneIds 的真实集号过滤，并保留出场不足3集的讲话配角与年龄阶段；人工编辑仍读取全剧讲话场景，防止从分集查看时误删其他集关联。音色批量操作和对白读取遵从分集范围。
- 分镜旧本地草稿若只是自动关联失效、正文和引用未被人工改动，修复数据到达后自动重载逐条素材；保留手改正文、手动增删引用及原视频参数。核心回归与三宽浏览器均覆盖持久化 pending 草稿恢复。
- 仅客户端与纯逻辑变更，无云端数据库或服务部署。卡密、账号、邀请码、Codex思考强度配置不在本次修改范围。
