# 2.8.156 验收

- 2.8.155 的直接父提交是 2.8.154 的 `d6cb32c`。两版安装包中 LibTV 网络、LibTV 服务、导演比重校验三个模块逐字节相同。2.8.155 修改了导演自动生成上下文，加入语速和时长规则；静态检查没有发现对分数作等分重写。2.8.155 的模拟回包不包含镜头比例，原验收未覆盖 v8.5 分数格式。
- 实际读取用户提供的 v8.5 压缩包入口及引用文本，识别为分数合同。整数分数精确求和，等价分数识别等时，不作分数重分配；旧百分比合同继续兼容。生成请求强调逐镜预演，模型核对同条等时有无原文依据，保留右侧草稿和提醒。
- 内容预估和实际切分分开。场景可见刻度和预计秒数/条数，点「应用到全剧」保存来源、尺度和上限。整本面板只显示已应用基准，切换场景或拖动滑轨不改它。各场按同一尺度独立估时，再根据对白、动作和模型建议找切点，保持原文完整。新最左端以当前场景校准一条容量；比例随已确认的参考场进入批次和恢复快照。校准秒数属于分段预算，超出自然表演容量提示核对。
- 隔离 Electron 实测，30秒/1条调至45秒/2条后应用到全剧，随后将场景滑轨调回正常，整本面板仍为45秒/2条。实际批次复用同一尺度，生成控制器保存两张卡片30/15秒。双倍内容在45秒尺度下约90秒/3条，在30秒尺度下60秒/2条。模型回包为模拟。
- LibTV 截图客户端显示 2.8.154。旧版真实任务只读记录多次网络失败且未取得节点，历史错误缺少具体命令阶段。系统代理启用时官网、四个 API 和四个素材域名均收到 HTTP 应答；真实 CLI 账号和视频模型只读成功。故障注入复现代理预检通过但新 CONNECT 断开，现于代理隧道尚未建立、CLI TLS 数据尚未发送时回退直连；不重发原命令。新错误含具体阶段。未发真实生成或素材上传，无法断定截图对应的原始单次故障由此造成。
- 同一测试集使用 Python 3.11 和并发 4 全量通过 3068/3068。默认 Python 3.14 的既有 WorkBuddy 用例在退出清理时报告测试进程身份不匹配，初次高并发另有本地 Like 回环请求短暂失败。生产测试及产品代码未因此跳过。
