# 2.8.171 验收（2026-11-15）

## 问题与定位

用户反馈 170 更新后“继续保存图片”和“重新生成图片”都仍得到参考图服饰。只读核对实际资产：描述要求浅灰 T 恤、藏青开衫、深灰家居长裤及拖鞋；旧 `characterVariantDifference` 遇到“妆造：”等标准字段后，仅保留白名单字段，丢弃前面的“服装改为……”自然语言整段。实际发送的提示词只剩参考日常西装及妆容。代码追溯：该字段筛选逻辑来自 8f598fdc，170 只修复 Electron 上传请求，不是此次筛选规则的引入版本。

本次明确复现的是提示词内容丢失，不能把“结果看起来像参考图”断言为供应商原样返回了同一文件。170 的上传验证未覆盖生成内容语义，是验收缺口。

## 修改

`core/collabStore.js` 以句段为边界只移除明确的重复身份字段、无实际值的标准差异字段；保留自然语言换装、身体变化、分号续写及其他未知描述。补齐已受旧逻辑移除的发型/发色字段识别。原描述及已有图片不改写。单张与批量共用同一提示词函数。Codex 测试改用内容不同的输入参考图和生成图，避免同图夹具掩盖输出替换。

## 验证

- 全量 3120/3120；构建通过。新增 5 个回归：实际换装描述、混合身份/自然语言身体差异、保存/编辑、分析发布、请求/新结果。
- 首轮全量出现 14 个旧入口测试失败，均为发型字段未移除；补齐字段后全量通过，未放宽旧测试。
- 真实 Electron 的 ArtSection 页面：使用实际描述的隔离副本，红色参考图和绿色输出图。真实 HTTP multipart 收到完整换装提示词和正确参考字节；真实返回新 PNG 并保存本地。首次保存模拟失败，“继续保存”仅上传同一新 PNG；再次点击生成再发一个请求。最终 2 次生成、2 次上传，预览 URL 与新输出相同，和参考图不同。1280/1920 截图已检查。证据 `output/171-ui.json`、`171-ui-*.png`、`171-ui.cjs`。
- 真实 Electron Content-Length 上传回归通过，防止 170 修复倒退。
- 独立复核：重新核对 diff、用户实际描述前后提示词、单张/批量共用路径、保存恢复语义及旧身份过滤测试。无生产数据修改、无真实付费生图调用。协议回归不等于供应商实际图像质量验收。

历史结果不会自动改变；“继续保存”只恢复此前结果。获得新造型需更新后明确重新生成（可能产生费用）。不自动丢弃历史结果或偷偷重新提交付费任务。
