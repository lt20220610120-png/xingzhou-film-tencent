# 2.8.199 发布验收

2026-11-23，LibTV 前置上传与项目协作分镜滚动修复。基线为 2.8.198 和 `3fabfb8`。

## 交叉复核

- 截图中的这次失败发生在第二条参考音频上传，代码尚未运行付费生成。2.8.198 只对四种明确的连接错误重试，CLI 省略错误码、连接重置与代理网关异常可能直接终止，隧道的失败细节也可能丢失。故障机截图缺少域名与错误码，无法确定其具体网络故障。
- 真实 Electron 基线在 1280px 的第二张分镜卡片首次删除图片时，恢复栏出现并换行，卡片头部从 53px 增至 99px，主区滚动随之从 1444px 移至 1490px。素材两行缩为一行会改变高度，底部还可能被浏览器钳制。
- 2.8.198 的主内容容器会跨分集和场景复用。手动切换保留旧偏移，视频池的持久化定位目标在重新进入分镜时还可能二次触发。

## 数据与边界

- 所有回归使用模拟上游、合成项目与临时窗口数据。未触发真实付费生成或改动用户项目。
- 桌面发布沿用现有云端 API 和授权，无后端部署需求。


## 修复与隔离回归

- 参考素材按原顺序逐个上传，每个素材最多三次，连接超时、重置、无错误码的请求失败、临时网关失败可刷新路由并尝试备用通道。错误输出包含阶段和可识别类别，保留官方域名及对应 OSS 存储桶边界。付费运行仅提交一次，未确认时继续查询原节点。
- 独立 LibTV 回归覆盖六张图片与两条音频、中断后的持续上传、代理 502、首路超时后切备路、持续断网、取消与换账号、拒绝非官方域名、付费掉线后按原节点恢复。Node LibTV 回归 61 项通过。
- 1280、1600、1920px 的 Electron 实测保持视口和分镜卡片位置。1280px 第二条分镜顶栏从 53px 增至 99px 时滚动位置维持 1444px。1920px 素材区域从 255px 缩至 133px，正中位置维持 2192px，底部位置维持 2946px，滚回有效内容后自动释放临时保位空间。
- 添加、导入和恢复保持视口，删除的关联在重新进分镜后仍保持删除状态。切集、切场、从总览进集的主区与左侧剧本实际均为 0px。视频池定位到目标卡片后，下一次普通浏览从顶部开始。
- 全量通过 3,250 项 Node、13 项发布 Python、12 项本地 Qwen 测试，Vite 构建通过。启动授权页的隔离回归覆盖免卡、无有效月卡拦截、网络重试和焦点恢复。
