# 2.8.87 发布验收

日期：2026-10-28。基线：2.8.86 / e1a6b01。来源：用户反馈全剧提示词发布等待久、过程不透明、切换页面后操作状态丢失，要求更高效发送。

## 实现与边界

- 原流程逐集串行，发布时重复写人工核实记录、场景历史和新上传 ID，并反复校验全剧。现按集最多 4 路 worker；store 的云端池同样限制 4 路、同集独立串行，本机检查点仍原子有序。
- action=publish 使用既有人工核实，不重新核实；完整有效已发布集跳过，网络/回执失败保留已有幂等请求 ID，下次继续。来源校验按目标场执行，包含同场新增/无效提示词；全剧局部可发布集合也必须场景完整。
- promptPublicationJob 按 API/账号/项目持有任务，页面卸载只取消订阅，不取消工作；清单、美术共用逐集阶段、实际并发、排队、耗时、失败细节。发布不调用大模型。
- 云端确认后节流刷新真实资产 ID，使用已有回执投影发布元数据，避免逐集重下全剧分析历史。保留未发布场景身份和旧服务端信息，不带入本地草稿卡片；提示词标记保存失败仍刷新已真实发布资产。
- 账号切换不等于页面切换：本机 checkpoint 固定 accountId，主进程同步核验；云端请求前后核验预期账号，防止旧任务向新账号发送或串写。
- 任务持续到当前软件进程结束；正常页面切换、分集切换不停止。退出软件后的恢复依赖已有逐集检查点及幂等回执，再次点击发布续做。未更改云端协议和权限；云端仍保留项目事务锁，真实提速受网络与服务器耗时限制。
