# 2.8.96 视频监测验收

日期：2026-10-30，Asia/Shanghai。

## 根因与实现

本机7条自动化视频任务中2条已在上游完成却停在downloading，提示“结果地址跳转”/“fetch failed”。Fnko旧下载器拒绝全部3xx且使用Node网络；Electron net.fetch又不适合手动跳转。新增media-read-transport使用Chromium net.request redirect事件逐跳处理；Fnko下载仅跟随最多5跳HTTPS，每跳重新决定凭据，仅原生自己的任务content接口可带APIKey，不带网页Cookie。系统网络出错可用第二条只读GET传输尝试；状态GET也改用系统网络。

generation-monitor在主进程按5秒扫描到期原任务，最多4个并发，拥有者/原配置域名校验、同一任务在途互斥、失败冷却，不含任何生成POST。generation-jobs保存检测时间、查询次数、上游状态和下载提示。生产任务状态机区分生成失败/查询失败/下载失败/未知提交；计数来自持久化明确失败任务，默认2次主模型，只有用户开启并指定备用后才切换。用尽不无界重新收费；暂停后可增加后续次数。

视频池本机任务先展示，云端读取和原任务查询独立并行，4秒刷新；成功数只在本地下载成功时增加。自动化分集区域默认折叠，按唯一提示词统计成功数/收齐集数，已成功结果可按集导出。
