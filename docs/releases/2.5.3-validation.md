# 行舟影视 2.5.3 验证记录

## 用户要求与实现

本项目按用户要求停止使用 frontend-design Skill，保留通透白色工作面与淡薰衣草紫按钮。清单页统一名称为「清单核实」；正文与逐场名称 18px，名单 16px，标签及按钮至少 14px。右侧三类条目使用独立白色卡片、浅色边线和轻阴影。Skill 库使用 Library 图标，与图视生成的 Sparkles 区分。

本集资产名单保持默认收起的三类汇总。逐场区域使用编号导航、上一场和下一场，一次只挂载当前场景。切换时保留完整账本，关闭旧弹窗并重置正文内部滚动；添加已有条目、补充信息卡、修改、移除、撤销、核实及发布功能保持原有语义。整集/全部操作仍处理各集全部场景。

所有核实编辑、关联、核实状态和模型分析中间结果通过原本机 art-review-checkpoints JSON 文件原子落盘；仅明确发布调用云端保存与发布接口。清单页不再定时刷新云端，保活的隐藏导演页面也停止轮询。发布后才刷新下游美术和资产。模型分析仍调用用户选择的 API。

未发布本机草稿优先于云端刷新数据。显式发布先上传必要的前集核实依赖，再上传目标并发布；前集依赖上传不额外建立前集资产。独立 cloudReceipt 保留未确认请求的原编号、版本和 payload，本机继续编辑后仍可在下一次发布幂等恢复旧回执，再上传最新稿；不会重跑模型或覆盖新编辑。云端版本冲突保留本地稿，明确采用云端时将旧稿另存历史。

发布期间离开项目，旧刷新回调不能拉回旧项目；进入本地核实页后，先前排队或等待云读取的自动刷新不能再执行导演同步。一次本地保存失败时，内存和磁盘保留上一份成功稿，并清除上次操作的成功提示。
