# 行舟影视 2.7.5 验证记录

本次处理豆包工作前台驱动问题、黑框相关后台进程、Gemini 1095、ChatGPT 网页账号入口与小说通读并发。

## 行为与边界

- 豆包生产文本桥不再运行 UIA、发送系统按键、写剪贴板、打开自动任务或编译 PowerShell 辅助程序。状态检查只检查客户端安装文件。已有配置请求返回 `DOUBAO_BACKGROUND_UNAVAILABLE`，不自动改用另一接口；登录按钮仍可由用户明确打开客户端。
- 没有找到普通豆包工作客户端可靠的外部后台调用接口，不能宣称已完成后台接通。公开资源中的内部 SSE、远程控制与 MCP 上下文依赖客户端运行时及授权，不作为已验证外部 API。
- WorkBuddy 更新中的 Python 调用选择 GUI 解释器，并在 Python 模块运行前初始化标准流。资料检查通过临时 JSON 文件回传，保留原数据路径校验。真实 Windows venv 检查验证 `GetConsoleWindow()==0`。未复现用户反馈的周期黑框，不把这一项验证等同于全部闪框问题解决。
- Gemini 1090–1099 分类为网页会话拒绝。仅在没有交付正文时刷新页面、重新发现账号模型并重试一次；保留所选模型。再次失败提示重新验证。网络中断、额度不足及部分输出均不重发。刷新等待新文档加载完成，避免继续读取旧页面会话。
- ChatGPT 使用行舟影视专用 `chatgpt-browser` 目录。正常登录窗口不附调试参数；后台调用使用账号网页 UI、临时聊天和网页当前默认模型。没有导出令牌、提取 Cookie 或调用付费 API/Codex。人工验证不会被自动绕过。仅返回本次请求之后、已完成的助手正文；纯 JSON 代码块去除网站语言/复制工具栏。
- ChatGPT 独立登录窗口已打开，目前尚未收到用户在该窗口完成登录的回复，因此真实账号调用待验证，安装包中的入口不能当成已接通证据。
- 并发通读可选 1–8 路，新项目默认 3 路，旧项目未设值时为 1 路。成功原文区间和旧缓存保留；输入或输出截断仍按 Unicode 边界分段。全部阅读记录按原文位置排序后再汇总，故事规划和正文转写保持原有顺序。网页账号桥目前顺序调用。
- 阅读池失败后停止分配新区间、等待在途结果保存后结束。停止操作取消全部活动请求，阻止后续汇总。并发设置不改变正文来源指纹，不使现有稿失效。
