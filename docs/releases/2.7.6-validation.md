# 行舟影视 2.7.6 验证记录

## 本机问题定位

- 对用户现有《重生之都市狂仙(501-1000章)》项目只读检查：原文 1,263,842 字符，547 条成功阅读记录，共 671,461 字符笔记；历次任务保留 289 条事实汇总和 51 条汇总错误。旧流程按章和 3,200 字区间读取、再反复汇总，是请求数量和耗时增加的明确因素。
- 旧 `validateMap` 确有最多100集及“单次分集规划超过100集”的硬性错误。没有代码要求全部章节都入选，但旧提示没有充分明确素材库可舍弃前后内容，且“靠后找终点”可能使模型扩大范围。本次不把模型行为的猜测当作已核实事实。
- 现有完整阅读及成功汇总保留，新规划复用缓存；目的性索引只用于选材，后续正文仍回到所选原文。初稿超过合理技术预算时，要求模型按目标篇幅重新选择主线起止，不能仅缩减集数却仍将全库压入剧本。
- 用上述真实原文和缓存、隔离模拟模型验证新流程：已有缓存时0次新原文读取、0次新汇总，新增1次选材规划和1次设定；冷启动时27次连续原文读取、0次汇总、1次规划、1次设定，共29次，原文覆盖完整1,263,842字符。此计数以模拟模型返回有效80集细纲及紧凑索引为条件，不是实际生成质量或耗时承诺。证据：`qa/v276-ip-cache-probe-result.json`。
- 实际章号从章节标题判断，不把目录的第一个条目当成小说第1章。真实素材含序段及第501章以后内容；新提示允许从适宜的中段故事起点开始，未选材料继续保留。
- 本机大资料快照单次 `JSON.stringify` 实测约87–91毫秒。浏览器缓存写入改为与已有250毫秒保存合并，减少并行进度更新时连续同步序列化；磁盘保存及配额失败不阻断保存的行为保留。

## ChatGPT 网页连接

- 在行舟影视专用浏览器资料目录复现后台网页标题“请稍候…”，没有输入框。旧英文验证识别遗漏中文标题，误报未登录；网页 readyState 完成后输入框仍可能未加载，旧检查也会过早误报。
- 使用普通 Edge 在 Windows 独立后台桌面运行，而非用户前台或无界面浏览器。专用资料目录与正常登录窗口保留；不读取普通浏览器配置、导出会话凭据、修改浏览器指纹或解网站验证。
- 网站人工验证与未登录分别提示。登录识别不等于真实正文返回；仅有实测返回才可视为账号已接通。
- 已定位第三个实际故障：新版 ChatGPT 页面移除了旧 `data-message-author-role` 标记，模型已在约12秒内回答，但旧代码找不到回复而超时。现在同时兼容新旧结构，通过当前请求的用户标记定位其后、下一用户消息之前的助手正文；不混入其他回复、页脚、复制工具栏或用户复制按钮。
- 用户完成验证后，本机账号同一后台实例连续实测返回“连接成功”和纯 JSON `{"ok":true}`，第二次无需再次验证或登录。后台浏览器 consoleWindow=0、userDesktopWindows=0、browserInForeground=false，前台进程前后均为9316。证据：`qa/chatgpt-native-v276.json`。该测试证明本机当前可调用，不代表未来网站验证、额度或结构变化不会影响连接。
- Windows 本地网页实测新旧 DOM 标记、未来回复和助手引用隔离、会话关闭后再打开保存、进程树退出及无前台窗口；启动失败/取消/超时立即释放专用浏览器，测试不读取普通浏览器资料。
- [chatgpt-web-provider 的开源说明](https://github.com/guberm/chatgpt-web-provider/blob/main/README.md)同样报告无界面浏览器遇到验证、正常浏览器可工作的差异。本机根因以本地页面与运行验证为依据。
