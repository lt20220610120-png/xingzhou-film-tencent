# 行舟影视 2.7.3 Implementation Plan

> **For agentic workers:** Use independent agents for IP pipeline, creator entry/text presentation, and Gemini feasibility; root integrates and verifies.

**Goal:** 落实用户明确要求的集数下限、紧凑入口、设定前置、干净成稿与 Gemini 网页账号接入。

**Architecture:** 保留小说原文、分集内容和收录快照的既有存储。规划和设定共享通读材料，输出与展示分离；Gemini 账号接入先验证会话来源，再接到现有本地模型桥接。

**Tech Stack:** React / Electron / Node.js；现有 Node 测试与 Playwright 页面验证。

**Spec:** 用户本轮截图与文字需求（2026-10-05），已授权直接继续更新。

## Global Constraints

- 60 分钟至少 50 集；120 分钟至少 80 集。旧项目保留，新规划及采用必须校验。
- 保留手工设定、已有正文和版本；收录快照不会随创作项目变化。
- 展示和成稿导出去掉 Markdown 标题前缀，正文内普通 # 保留。
- 每集只输出一个集标题，原文导出保持原文。
- 不输出账号凭据，不关闭用户正在用的浏览器；不使用 frontend-design Skill。
- 测试、页面、安装包与公开更新清单完成验证后发布新版本。

## Review Focus

- 旧 43 集项目可以继续阅读，不应被自动补集或丢稿。
- 规划失败后设定与通读记录可恢复；已有手工设定不能被自动替换。
- 仅剩设定未生成时，一键完成仍可操作且状态清楚。
- 纯文本、Markdown、CRLF 与章内故事边界都应保持可编辑。
- Gemini 会话过期、离线或未登录应返回明确状态，不应误报接入完成。
