# 自主接入视频模型（2.8.26）

用户要求：输入地址和密钥、拉取或手写模型后即可在图视生成使用；新型号无需再次发版。保留现有任务、旧配置和图片功能，不自动发送付费探测。

根因：modelChoices/GenerationComposer/feituo-client 分别硬编码型号；ModelImport/addMediaProfile 丢协议和参考能力；自定义视频一律使用 Ark 请求；非 ft 任务没有可恢复的通用任务查询。

执行方式：按照工作区约定直接在本会话实现、独立复核、验证、发布。

1. 模型目录：将已拉取列表按配置保存；支持刷新一个已有配置的目录、保留选中及待处理任务型号；生成端合并目录和手填型号。能力统一保留分辨率对应时长、参考限制、音频依赖，未声明不假定无限。
2. 协议：FT 标准、Ark、Videos JSON、Videos multipart，以及用户编辑的声明式 HTTP 配置。模板覆盖提交/查询路径、HTTP方法、鉴权头、请求 JSON、返回 ID/状态/视频地址路径及成功失败状态。模板只替换已知变量，不执行代码，不从上游下载可执行配置。
3. 任务：保存提交得到的 ID、协议和非秘密参数；轮询失败可重试查询和下载，绝不重新提交；重启仍可恢复。不将密钥写任务文件，不将供应商密钥发送到视频存储主机。
4. 界面：API 编辑提供读取目录、协议和参数，特殊协议可编辑 JSON 模板与映射。模型拉取时提供视频协议选择。图视生成显示手填/新拉取型号，并将相应能力和协议送到实际提交端。
5. 验证：用未出现在内置目录的虚构型号证明导入→保存→选择→提交→查询→下载→重启恢复全链路；模拟 FT、Ark、Videos 与不同字段命名的自定义上游；禁止付费接口测试。全量测试、真实界面和安装包验证后发布并核验下载，更新软件更新记忆。

边界：只配置支持 HTTP JSON/multipart 的服务；要求专用 SDK、动态签名、浏览器登录或只有 webhook 的服务不能宣称仅凭地址密钥自动兼容。未知协议不会自动尝试多次付费提交，需用户按文档选协议或配置模板。
