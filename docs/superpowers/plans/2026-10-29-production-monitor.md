# 制作监测与 Agent 状态实施计划

目标：开始/恢复时批量核实已有成果，按场景定位缺项，已完成成果不重复生成、关联或发布。管理员能看到实际接续依据和 Codex 账号、额度、Skill 信息。

设计：以导演项目、协作项目、清单发布签名、当前提示词绑定、图片及视频任务凭据为事实来源；一次批量读取后在内存比较，检测不调用模型。保存逐场监测快照和时间。发布完成与关联准确性分开：已有有效关联可继续，疑点记录，不以全量完美为门槛。正文变更和来源冲突单独提示，不覆盖原成果。暂停不清空成果；恢复只处理缺项。

- [x] core/productionMonitor.js：纯函数计算逐集逐场完成证据和增量工作集；测试已发布、局部缺项、过期正文、部分关联。
- [x] productionAdapters/controller：接入监测，去掉已发布场景的重复审核，限定补关联目标，增加只读刷新；验证暂停恢复、没有重复云端发布/AI调用。
- [x] production-agent：通过官方 app-server 获取脱敏账号、限额窗口、Skill 元数据；不返回令牌；失败/不支持按项呈现，不影响已建立的模型连接。
- [x] UI：监测完成度、可展开缺项与变更证据、账号/真实额度/Skill 面板，保持滚动对话；模拟 UI 与只读本机接入验证。
- [x] 独立复核47项、npm test 2517项/build、三宽界面验证、打包运行时检查通过，已发布2.8.94，三份公开清单签名及安装包Range核验通过，更新交接与软件更新记忆。

并发：已有池限制清单场景/描述并发2，发布仅未完成场景按集分组并发4，生图/视频使用用户配置。视频任务持久化后再轮询；原片齐一集才超分，Topaz 单队列；超分齐一集才剪辑，剪辑单队列。不同集的视频生成、超分、剪辑可交叠，依赖检查不以目录文件数量代替任务身份。

接入依据：https://developers.openai.com/codex/app-server 及 https://github.com/openai/codex 。同时用本机 Codex 生成协议 schema 核对字段。窗口按服务返回的分钟数识别，未返回5小时/周额度就明确显示未提供，不推算。Skill 统计为当前连接工作目录发现且启用的数量，不假定它们都在每条任务中被调用。
