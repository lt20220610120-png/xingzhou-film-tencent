# 行舟影视 · 创作空间重构讨论稿 v0.1

日期：2026-10-04。状态：待讨论、未定稿、未授权开发。

本稿根据用户本轮完整口述和截图整理，并只读参考现有创作者与导演工作台代码。本文是产品设计提案，不代表已实现、已测试，也不将 AI 补充的规则视为用户已确认决定。本轮不修改产品代码、不安装外部项目、不发布软件。没有承诺“零 bug”；本文用明确的数据关系、失败处理和验收场景降低后续遗漏。

## 1. 需求来源和设计边界

### 1.1 用户已经明确的要求

- 打开软件仍有导演工作台、创作空间两个身份。导演工作台的功能和效果已满意，本次重构创作空间。
- 创作者主入口仍为果子库、创作剧本、剧本库，保留 Skill 库、API 接口等公共能力。
- 果子库用于沉淀对成熟剧的反推剧本，保留项目、分组、总稿、分集、视频上传、文档上传、直接输入、Skill 转换、模型选择和导出；重点缩小标题及工具区，改为左右对齐的输入和输出。
- 创作剧本保留洗稿、原创两条通道。本文暂沿用“洗稿”名称；“对标改写”是可供讨论的界面名称，尚未替用户改名。
- 洗稿项目以一部对标剧本为中心，可从果子库选择或上传文字文档。拆解设定、大纲、细纲、事件、人物及人物线、分集内容；每项有对应的新作品编辑内容。
- 洗稿左侧展示来源，右侧独立保存新作；可以添加集数，选择模型和 Skill 协作，项目全部 AI 输出进入沉淀池。右侧整套新作可导出。
- 原创包含自由创作和框架式创作，两种项目独立创建、共同归入原创、用标签区分。
- 自由创作有可编辑目录、总稿和分集；左侧自己写，右侧 Agent 转换，两侧分别整部导出。
- 框架式创作是核心：从零碎灵感与设定开始，通过持续对话共同整理事件、时间线、总纲、骨架、人物线、世界模拟、细纲、分集故事正文、分场剧本，最后汇总导出。
- 框架式项目可上传 1—3 份核心对标材料，材料可以是完整剧本或记录，提炼节奏、反转、时间线等经验，支持不同模型参与且保留上下文。
- 世界模拟基于确定的世界规则、人物、骨架和事件，探索可替换的更好路径，由人选择。
- 框架式创作最终导出只含确认后的分场剧本正文，不含头脑风暴、推演、设定讨论等过程材料；TXT、Word。
- 剧本库展示已经完成的作品，在软件内直接阅读全文，本期以展示为主。
- 美术沿用导演工作台，重视完整、顺畅、结构清楚，细致能力可后续深化。
- 本轮补充确认：框架式创作主页面采用“成果编辑为主，右侧聊天”，左侧切换阶段。

### 1.2 本稿新增、尚待用户讨论的建议

1. 所有输出都留存，但按“素材／讨论候选／当前采用／历史版本”区分，防止弃用设定混入正式故事。
2. 果子、洗稿、自由创作采用双栏工作区；框架式“目录＋成果编辑＋右侧聊天”已获用户确认，其具体尺寸和按钮排布仍待讨论。
3. 事件和人物只有一份正式记录；大纲、骨架、细纲、时间线是这些记录的不同组织方式，避免多份文本各改各的。
4. 骨架节点可以锁定；世界模拟只产生候选分支，采纳前展示影响范围。
5. “收录剧本库”保存一个完成版本，继续写不会静默改变已收录作品。
6. 第一版提供内置经验提炼和有限轮次的剧情推演；后续再评估接入外部引擎。
7. 不让整个创作流程变成必须逐页通过的表单，可以先写任何已有想法；在需要依赖的动作发生时指出缺少的信息。

### 1.3 现有程序的只读观察

参考文件：`tencent/src/App.jsx`、`tencent/src/v06/ProjectCardHub.jsx`、`tencent/src/v06/DirectorWorkspace.jsx`、`tencent/src/brand-theme.css`、`tencent/src/production-workspace.css`、`tencent/core/projectStore.js`、`tencent/core/skillContext.js`。

- 果子和创作的分集页目前是输入在上、结果在下，结果区在生成后出现；重构为从一开始就并列可见的两个区域。
- 已有项目分组、项目卡片和 Skill 完整文件附加机制，可延续其能力，不应只把 Skill 名称发给模型。
- 总稿目前存在独立文本和逐集汇总两种来源；新设计必须明确它们的关系，不能让总稿与分集同时成为相互冲突的最终稿。
- 当前果子上传处理代码中，文本文档会读取文本，视频会记录“等待视频转录”；文件选择器列出 Word 扩展名不等于该路径已经完整支持 Word 解析。后续实施须验证真实导入链路，不能据按钮外观声称可用。
- 现有剧本库列表偏向摘要和下载，新版需要完整阅读页。
- 项目 AGENTS.md 记录用户不使用 frontend-design Skill 的偏好；本稿最终视觉依据是导演现有界面、截图和本轮要求。

## 2. 总体组织方案

比较三种页面组织：

| 方案 | 长处 | 主要问题 | 建议 |
|---|---|---|---|
| 所有模式统一左右两个编辑框 | 学习成本低，容易对标 | 框架创作的聊天、事件关系和正式结果容易挤在一起 | 用于果子、洗稿、自由创作 |
| 所有模式统一聊天主页面 | 灵感输入自然 | 正式成果埋在对话里，逐集编辑不直接 | 不作为统一方案 |
| 共用项目与 AI 基础能力，按创作任务使用两种工作区 | 兼顾文本工作和持续协作 | 要清楚规定共享数据与不同页面之间的关系 | 推荐 |

推荐的信息架构：

```text
身份选择
├─ 导演工作台
└─ 创作空间
   ├─ 果子库
   │  └─ 分组 → 项目 → 总稿 / 分集 → 原始内容 / Skill 输出
   ├─ 创作剧本
   │  ├─ 洗稿
   │  │  └─ 分组 → 项目 → 来源拆解 / 我的新作
   │  └─ 原创
   │     ├─ 自由创作项目
   │     └─ 框架式创作项目
   ├─ 剧本库
   │  └─ 已完成作品 → 版本 → 软件内阅读 / 导出
   ├─ Skill 库
   ├─ API 接口
   └─ 设置等现有公共入口
```

原创列表顶部为“全部原创／自由创作／框架式创作”过滤，卡片保留模式标签。洗稿与原创项目保持各自分组和过滤上下文；切换通道不会改变当前项目的模式。暂不提供会丢失结构的直接模式切换。

项目列表保持简洁：标题、模式标签、所在分组、当前阶段或完成集数、最后编辑时间。卡片本体用于打开项目；“更多”收纳重命名、移动分组、删除。列表上方放搜索、分组筛选、新建分组、新建项目。删除分组仅将项目移到未分组。

新建项目：

| 入口 | 必填 | 可稍后补充 | 创建后落点 |
|---|---|---|---|
| 果子库 | 项目名 | 来源、分组 | 总稿或首集输入 |
| 洗稿 | 项目名 | 对标来源、分组 | 来源导入页；已有来源则进入解析预览 |
| 原创·自由 | 项目名、模式 | 分组 | 首个编辑节点 |
| 原创·框架 | 项目名、模式 | 初始灵感、目标时长、分组 | 灵感与设定 |

框架项目允许只有一句灵感就建立；不以“未填完整设定”为由拒绝开始。

## 3. 视觉和布局基准

### 3.1 沿用导演工作台的样式

现有颜色依据：白色工作面 `#FFFFFF`、浅灰背景 `#F7F9FC`、深色正文 `#232B38`、次级文字 `#647084`、淡紫选中态 `#EEE9FA`、紫色主操作 `#7563BF`，边线 `#E1E6EE`。使用当前黑体字体体系，不引入新装饰风格。

建议尺寸是讨论稿，需在真实窗口及 Windows 缩放下确认：

- 全局导航约 176px，可折叠；项目目录约 180—220px，可折叠。
- 工作区顶部使用单行路径、项目名、保存状态和主要操作，约 48—56px 高。
- “第1集”采用约 20—22px 的可编辑标题，不再占据大面积输入框。
- 功能按钮约 32—36px 高，工具栏可换行；输入方式放在紧凑一行。
- 编辑正文约 15—16px，行距约 1.7—1.9，可调整字号；缩小的是外框与工具，不能靠缩小正文腾空间。
- 双栏默认等宽，可拖动分隔线；标题栏、编辑框顶边及底部状态对齐。
- 聊天和大量输出可独立滚动；页面工具区可自然向下扩展，避免三个嵌套滚动条同时争夺鼠标。
- 双栏宽度不足时可切换单栏聚焦、先折叠目录；聊天变为可展开侧栏，不能压住正在编辑的文本。
- 聚焦、运行、失败、保存状态都显示文字，不只靠颜色；图标按钮有名称提示。

### 3.2 双栏工作区线框

```text
全局导航 │ 项目目录 │ 返回项目 / 项目名 / 当前节点     已保存   导出 ▾
         │ 总稿     ├────────────────────────────────────────────
         │ 设定     │ 当前节点标题        输入或来源工具
         │ 第1集    ├────────────────────┬───────────────────────
         │ 第2集    │ 左侧标题           │ 右侧标题
         │ ……       │ 原始内容或自写内容 │ 输出或我的新作
         │ ＋添加   │                    │ 即使空白也始终可见
         │          ├────────────────────┴───────────────────────
         │          │ 接口/模型  Skill  参考范围  补充要求   运行
```

### 3.3 框架式工作区线框

```text
全局导航 │ 阶段目录 │ 项目名 / 当前阶段       已保存   项目资料   导出
         │ 构思     ├────────────────────────┬────────────────────
         │ 设定     │ 当前阶段的正式工作面   │ 项目协作聊天
         │ 事件     │                        │ 模型 ▾  Skill ▾
         │ 时间线   │ 编辑文字 / 事件列表 /  │ 正在参考：当前阶段
         │ 故事     │ 人物线 / 骨架关系      │ 对话历史
         │ 总纲     │                        │ 修改建议及影响
         │ 骨架     │ 草稿、已采用状态可见   │ 采纳 / 调整 / 留备选
         │ 人物     │                        │ 输入框      发送
         │ ……       ├────────────────────────┴────────────────────
         │ 成稿     │ 本阶段操作 / 需要复核的关联内容
```

框架式作品进到“故事正文→分场剧本”时，中间工作面可以切成前述双栏，聊天收起或按需展开，避免同时挤入四个正文区域。

## 4. 果子库

### 4.1 工作流程

创建项目 → 导入或输入素材 → 确认分集 → 选择 Skill、接口和模型 → 转换 → 右侧编辑结果 → 导出或供创作项目选择。

本期不增加额外的强制拆解流程。果子库主要保存已有材料及反推结果，拆解发生在创作项目需要使用材料时。

### 4.2 页面与操作

| 位置 | 按钮或功能 | 行为 |
|---|---|---|
| 目录顶部 | 总剧本 | 按集展示整部内容；可切原始稿、转换稿 |
| 目录 | 第1集、第2集等 | 切换本集，分别保存输入、输出、运行配置 |
| 目录底部 | 添加集数 | 新增一集空白输入、空白输出 |
| 紧凑工具栏 | 视频上传 | 保留媒体源；展示解析状态，得到可编辑文本才进入文字转换；能力不可用时明确告知 |
| 紧凑工具栏 | 文档上传 | TXT、DOCX 为第一版明确支持目标，解析后预览；旧 DOC 需真实转换支持，否则提示另存为 DOCX |
| 紧凑工具栏 | 直接输入 | 定位左侧编辑框，不清空已经导入的内容 |
| 左栏 | 原始内容／沉浸式对话 | 保留现有自由输入作用；不自动扩展成另一套常驻聊天系统 |
| 右栏 | Skill 输出 | 初始即为空白编辑框；生成后可手动改，保留修改历史 |
| 执行栏 | 接口、模型 | 从已接入 API 中选本次可用模型 |
| 执行栏 | 选择 Skill、查看 Skill | 选择完整 Skill 包，可看到附属文件清单 |
| 执行栏 | 运行转换、停止 | 按当前 Skill 处理左栏；输出草稿不覆盖人工已修改稿 |
| 顶部 | 导出本集／导出整部 | 先明确导出原始稿或转换稿；右栏空白时不偷偷以左栏补位 |
| 结果工具 | 历史、恢复、复制 | 查看或恢复某次结果，恢复前保留当前版本 |

总稿与逐集使用同一套内容源，详见第 10 节。无集号的长文可先作为总稿保存，再预览分集；已有明确集号优先按原号拆分。

## 5. 洗稿工作区

### 5.1 来源与新作的关系

左侧为对标剧本及其拆解，右侧为独立的新作品。两个方向的数据不能混写。所有栏目都允许查看对标、编辑自己的版本；右侧默认空白，只有用户主动选“沿用到右侧”才复制选中内容。

从果子库选择时明确选择原始稿还是转换稿，生成有来源信息的项目快照。以后果子库变化只提示“来源有更新”，不自动改变此项目；点击更新来源时展示差异和受影响分析，新作仍保留。

上传保留原文件和提取文本。导入预览显示：文档名、已识别集数、缺失或重复集号、是否存在序言或设定。不确定分段由用户纠正；拆解不能把猜测补写成原文。

### 5.2 左侧目录和双栏含义

| 栏目 | 对标一侧 | 我的新作一侧 | 主要操作 |
|---|---|---|---|
| 原剧本 | 全文和原集目录 | 当前新作全文预览 | 导入、更新来源、查看来源位置 |
| 设定 | 类型、题材、核心脑洞、世界背景、主角特点 | 我的对应设定 | 一键提取、沿用所选、编辑、AI 协作 |
| 大纲 | 从开端到结局的大事件、时间顺序和因果 | 我的大事件及故事方向 | 分析大纲、调整、对照 |
| 细纲 | 大事件下的细化过程 | 我的细化过程 | 展开大事件、补充过程、检查衔接 |
| 全部事件 | 按阅读顺序编号的完整事件清单 | 我的事件清单 | 提取、新增、拆分、合并、排序、筛选 |
| 人物与人物线 | 全剧人物及从出场到结局的轨迹 | 我的角色与命运线 | 提取、编辑、关联事件、按重要程度排序 |
| 分集创作 | 原第N集全文，可切本集细纲 | 我的第M集内容 | 选择对标集、添加新集、编辑、Skill 辅助 |
| 整部预览 | 对标全文 | 我的整套作品 | 预览、导出、收录剧本库 |

“敢爱敢恨”等放在人物特点，不强行识别为金手指。没有特殊能力的作品可记录“无超常金手指”；核心故事设定仍可有独特性。AI 提取的每项提供原文位置；无明确依据则标注推断或未提及。

细纲、事件、人物的关系：同一个事件可以属于一个大事件、涉及多个人物、跨越多个分集。人物线是从人物角度看相关事件，不把相同事件重新复制存成几份独立事实。

### 5.3 拆解流程

“一键拆解”打开范围选择，默认设定、大纲、细纲、事件、人物与分集索引。每个模块也能单独运行。

1. 读取完整来源，建立集号与来源位置索引。
2. 分段提取，再整剧核对，产出各模块候选；显示真实覆盖范围。
3. 完成的模块可先查看，失败模块独立重试。
4. 人工修改过的拆解不被重跑覆盖；新旧结果可比较后替换。
5. 原文未给结局时明确记录“材料止于……”，不补出所谓真实结局。

普通分集展示只要来源有集号就可以开始，不必等待全剧 AI 拆解完成。

### 5.4 分集对标和独立新集

默认原第1集对应新第1集，依次创建空白新集。另提供“添加新作集数”，并允许新集关联零个、一个或多个对标集。新作可以比原作长或短，不要求强制一一对应。

左栏上方：`原第3集 ▾`、`全文／细纲`；右栏上方：`新第2集`、`本集目标`、`历史`。新集固定关联到记录 ID，后续调整显示集号不丢失关联。

AI 默认工作对象是当前左栏对标内容，参考全剧和项目沉淀；新作已确认的人名、世界规则、已写前集决定输出的连续性。对标事实不能压过新作已确认设定。发现二者冲突，提出处理方案或发问，不自行退回原作设定。

每次生成默认是“本集建议稿”。可选择插入选中位置、替换选中文段、追加、整集替换。整集替换前展示差异；已有人工内容永远可恢复。

### 5.5 导出

默认“导出我的完整作品”：按固定顺序输出右侧设定、大纲、细纲、事件、人物线、新作各集正文，允许勾选章节。提供另一个预设“仅导出剧本正文”。

右侧空白栏目显示缺项，可明确跳过；不从左侧对标补入，不混入原文、聊天记录或未采用 AI 备选。支持 TXT、DOCX，预览就是即将导出的内容。

## 6. 原创·自由创作

目录支持总稿、设定、人物、自定义章节、分集。通过“添加内容”选择节点类型，保持用户可自由命名的习惯；“设定”不会因为排在第一行就被当成“第1集”。

| 功能 | 设计 |
|---|---|
| 左栏 | 我的原稿，随时直接编辑 |
| 右栏 | Agent 转换稿，初始空白，可手改 |
| 目录操作 | 添加内容、添加集数、重命名、排序、移除；移除可撤销 |
| AI 执行 | 选择接口、模型、Skill；当前节点为主，可参考指定前集及项目资料 |
| 执行结果 | 生成候选、对比、采用到右栏；重跑保留之前结果 |
| 总稿 | 切换“原稿总览／转换稿总览”，按节点结构汇总，可定位到对应节点编辑 |
| 导出原稿 | 全部左侧内容，按目录顺序组成一个文件 |
| 导出转换稿 | 全部右侧内容，按目录顺序组成一个文件 |
| 收录剧本库 | 明确选原稿或转换稿，并预览收录范围 |

模型转换不要求先有完整大纲，保持用户想写哪里就写哪里的自由。左右两份长期并存，没有“转换了就删原稿”的行为。缺失转换稿不能默默用原稿填满。

## 7. 原创·框架式创作

### 7.1 核心体验

用户可以连续倾倒灵感，与 Agent 商量、修改、比较；中间工作面持续显示当前阶段的成果。对话中出现明确的新内容时，Agent 生成可操作的“整理建议”，说明放在哪里、改变什么；用户可整项或分项采用。

用户直接在成果区编辑会自动保存草稿。影响后续生成的内容有“设为当前采用”状态；不要求每个字点击确认。对关键设定或骨架的变化，集中展示需要复核的下游内容。

阶段目录分成“构思／故事结构／成稿”三组，默认展开当前组。顶端显示当前阶段，允许跳转和回看，避免十多个标签平铺在顶部。

### 7.2 术语约定

| 术语 | 本项目中的具体含义 |
|---|---|
| 灵感事件池 | 尚未决定使用、尚未排顺序的零碎故事想法 |
| 总纲 | 打算采用的大事件及各自作用，可先不精确排顺序 |
| 骨架 | 大事件按顺序和因果串联，并标明开端、关键转折、结局等节点 |
| 全部事件 | 将骨架落实为可发生、可表演的具体行动及结果 |
| 细纲 | 已采用的具体事件按叙事顺序展开，衔接各个大事件 |
| 分集细纲 | 将细纲事件分配到集，记录每集目标与结尾衔接 |
| 故事正文 | 人和 Agent 写出的本集详细内容，尚不强求分场格式 |
| 分场剧本 | 故事正文整理为集号、场号、场景、日夜、内外、人物、动作和对白 |

这些栏目保留用户需要的不同观察角度，但不建立八份互不相干的故事。总纲到骨架是增加顺序与因果；骨架到细纲是增加具体过程；分集是内容编排；分场是正文格式整理。

另外区分三个维度：故事实际发生时间、观众看到的叙事顺序、事件之间的因果。倒叙不会改变事件实际发生时间，“先发生”也不自动等于“导致”。

### 7.3 各阶段界面、按钮和 Agent 职责

| 阶段 | 中间工作面 | 按钮 | Agent 职责及结果 |
|---|---|---|---|
| 灵感与核心设定 | 灵感输入、类型题材、核心脑洞、世界规则、已定内容、待讨论项 | 整理我的想法、补充灵感、采用、锁定、讨论冲突 | 从原话提取，不把建议冒充用户决定；展示矛盾双方和来源 |
| 零碎事件 | 编号事件列表、事件描述、相关人物、候选状态 | 添加事件、从聊天整理、拆分、合并、留作备选 | 将一段灵感拆成可理解事件；不为了编号擅自决定先后 |
| 时间线与因果 | 事件顺序、原因与后果、未连接事件 | 排列建议、手动排序、连接因果、比较方案 | 按用户目标给有限个候选顺序，指出断点和代价，不声称客观最优 |
| 核心对标 | 1—3份材料、阅读范围、经验条目、来源证据 | 从果子库选、上传、提炼经验、核对来源、启用经验 | 理解节奏、反转、伏笔兑现、信息揭示与时间组织，生成项目经验候选 |
| 总纲 | 大事件清单、起点与终点、故事作用 | 整理大事件、添加、拆分、合并、采用 | 根据现有想法提出大事件，不凭空填满整部剧 |
| 故事骨架 | 已排序大事件、因果连接、关键节点 | 串联骨架、检查因果、锁定节点、查看影响 | 形成贯通主线，发现过渡不足或结局缺口，协商后定稿 |
| 人物与人物线 | 主次人物、目标、性格、关系、知道的事情、起止状态 | 添加人物、梳理人物线、查看相关事件、检查冲突 | 按故事世界推演人物轨迹；区分剧情明示和补充建议 |
| 全部事件 | 具体事件与所属大事件、出场人物、前置条件、结果 | 细化大事件、添加事件、关联骨架、检查遗漏 | 将大事件拆成具体过程，保留每个事件用途及因果，不只给摘要 |
| 大世界模拟 | 选定时间段、固定条件、可变条件、候选分支及影响 | 设置推演、开始、停止、比较、继续讨论、采用分支 | 在锁定骨架和世界规则下探索人物行为与交叉事件，返回候选及违反约束提示 |
| 细纲与分集 | 大事件展开后的事件链、分集分配、每集目标和衔接 | 汇成细纲、分集建议、添加集数、调集、检查连贯 | 串起采用事件，提示缺口、人物知识穿越、重复事件、铺垫未兑现 |
| 故事正文 | 本集细纲与可编辑详细正文 | 展开本集、续写选段、改写选段、检查、确认本集 | 根据当前集目标写细节和对白，尊重前后集事实，不自动写完整季 |
| 分场剧本 | 左侧故事正文、右侧分场文本 | 按场整理、查看差异、编辑场景、确认终稿 | 组织为规范场次，保留因果和对白；不明场地或日夜标为待确认 |
| 整部终稿 | 按集按场的阅读预览、待处理清单 | 检查全剧、导出正文、收录剧本库 | 检查结构和内容一致性，修订建议由用户选择 |

核心对标可以随时补充，不强制必须上传三本才能继续；对没有对标材料的推演，不显示“已参考对标经验”。

### 7.4 对话如何真正参与创作

聊天在项目内持续保存，可按阶段筛选，也可搜索全项目。切换页面不清空对话；每条对话保存当时所属阶段和模型。

示例仅说明交互，不是用户确认的故事设定：

```text
用户：女主能听到男主心声，但只能在很近的时候听到。
Agent：整理了两项设定：读心能力、距离限制。
       还有一个待定项：是否只对男主有效？
       [采用两项设定] [修改后采用] [继续讨论]

用户后来：她在楼下听见他在楼上的心声。
Agent：这与已采用的距离限制可能冲突。
       [调整这场戏] [讨论能力升级] [修改距离规则]
```

重要行为：Agent 可以建议，但不替用户悄悄把限制改掉。采纳时要说明影响了哪些设定和事件；保留被替代的旧版，但不再当作当前事实。

多模型参与采用“同一问题的不同建议”方式：模型 A 出方案、模型 B 检查，或用户主动让两种模型比较。不同模型的结果各自留存；不存在多数模型投票就自动成为正式剧情。默认单模型，按需增加，避免每次闲聊自动触发大量调用。

### 7.5 核心对标的经验提炼

不只生成故事摘要。建议每条经验包含：

- 经验名称与适用场景。
- 材料中的具体集、场或段落依据。
- 使用的节奏、反转或信息差方法。
- 所依赖的人物动机、铺垫和世界条件。
- 应如何迁移到当前故事，以及哪些表面情节不应直接套用。
- 限制、反例和证据强弱。

经验默认仅在本项目启用。选择“保存为 Skill”后生成可检查的 Skill 草稿及参考索引，经用户整理再加入全局 Skill 库，不能自动污染其他项目。

它属于从材料提炼可复用写作方法，不等于训练模型参数，也不能保证拥有作者的全部创作经验。对标材料是片段或笔记时，显示覆盖范围，不能推断未提供部分的节奏与结局。

### 7.6 大世界模拟：第一版就能用的范围

本功能提供有约束的剧情候选，不把“推演”说成准确预测。

操作步骤：

1. 选择推演范围，例如某个大事件前后、指定人物、若干集。
2. 从当前采用版本生成快照，列出世界规则、人物状态、已发生事件和已锁骨架。
3. 设定固定点、允许改变的事件、分支数和轮次；提供“希望改善什么”，例如动机、生活感、冲突或伏笔。
4. Agent 逐步记录角色行动、彼此影响、世界状态变化和走向骨架节点的路径。
5. 返回有限个候选，每个有事件链、人物动机、成立条件、因果问题、优缺点、对后续内容的影响。
6. 用户可采纳一个完整分支或选取其中一个事件，查看替换范围后写入当前故事。

默认“骨架不变，探索过程”。需要讨论其他结局时，另开“探索骨架变化”分支，不能覆盖原骨架。不能在约束下走通时，应说明冲突点，不得硬凑结果。

举例仅用于交互说明：固定“男女主通过母亲认识”，比较拾包归还、帮忙处理误会等不同过程；只有用户选中某个过程，它才进入细纲。

第一版的“开始推演”必须有真实的模型运行、分支结果、比较、采纳和历史，不能用未来接入 MiroFish 的空按钮代替。外部模拟引擎未来复用同一输入快照和候选结果结构。

### 7.7 从细纲到可导出的剧本

目标时长可设为 60 分钟、120 分钟或自定义；总集数和单集目标可调整。时长只作估算，不以字数换算保证实际表演时长，也不为凑时长自动注水。

分集细纲 → 本集故事正文 → 确认内容 → 按场整理 → 人工核对 → 确认终稿。

分场示例仅说明格式：

```text
第1集

1-1 咖啡店 日 内
人物：角色甲、角色乙

△角色甲推门进入。
角色甲：……
角色乙：……

1-2 街道 夜 外
人物：角色甲

△……
```

场景变更需明确分场；地点、日夜、内外、人物名单可手改。原文无法确定的信息标为待确认。格式转换原则上不改故事；若需补写过渡，先作为建议，不夹带新增剧情。

终稿确认后若上游故事正文改变，对应分场稿标记“需要复核”，旧终稿仍保留。导出前集中提示未确认场次、缺集和未处理冲突；用户可继续编辑或明确导出当前草稿，草稿状态只放在导出预览和文件命名，不混入剧本台词。

框架模式默认导出仅采用后的分场终稿，按集和场号排序；不含设定、总纲、模拟、聊天、未选方案。若以后需要“项目资料包”，做成独立动作。

## 8. 共用的项目沉淀池、模型与 Skill

### 8.1 沉淀池保存什么

用户看到的名称建议为“项目资料”，其中可打开“全部沉淀”。

| 类型 | 是否保存 | 默认能否当成当前故事事实 |
|---|---|---|
| 导入原稿、视频转录、对标书、用户笔记 | 是，含来源 | 只能按各自来源身份引用 |
| 用户和 Agent 的聊天 | 是 | 明确采用的决定可以；闲聊或假设不可以 |
| 每次 AI 结果和模拟分支 | 是，包括未采用结果 | 不可以，除非已采用 |
| 当前采用的设定、事件、人物和正文 | 是 | 可以 |
| 人工编辑草稿 | 是 | 当前任务可读取，需明确草稿身份 |
| 已替代版本、弃用候选 | 是 | 默认不参与生成，主动比较历史时可调取 |

全部输出进入沉淀池与“每次把全部历史当事实”是两件事。每条记录带项目、栏目、来源、版本、状态，资料不能跨项目误用。

### 8.2 每次 Agent 如何读取上下文

执行栏提供“参考范围”，默认由当前任务选好，用户可查看并附加资料：

1. 本次任务、所选 Skill 及其完整规则文件。
2. 当前主要编辑对象：洗稿的当前对标集、自由创作当前原稿，或框架式当前阶段。
3. 当前采用的核心设定、人物状态和已锁骨架。
4. 与当前对象有关的前后集、事件、人物线、对标经验。
5. 相关对话摘要、明确决定及必要的原始对话。

完整剧本与全部项目资料可被查询，不假装无限长材料能在一次请求里完整塞入。能容纳时附全文；超长时按集分块读取和检索，保留原文定位与覆盖记录。整剧拆解须覆盖全稿，不能只检索几段就声称完成全剧分析。

用户指定“完整读全剧”时采用分批任务并展示进度；不能静默截断。当前集内容和适用 Skill 缺失、超长且无法处理时，先解决缺口再生成。

模型切换之后，项目记录和当前采用内容仍从项目存储装入，不依赖上一模型的私有记忆。摘要必须保留决定、未决问题和来源链接；历史原文可追溯。

### 8.3 统一执行栏

| 控件 | 作用 |
|---|---|
| API 接口 | 选择已配置的服务连接，界面不展示密钥 |
| 模型 | 可搜索服务中已配置或已获取的模型；手工补充模型名；不兼容当前任务的模型显示原因 |
| Skill | 果子转换必选，其他聊天可不选；所有已导入 Skill 可查找，缺依赖显示详情 |
| 查看 Skill | 展示主文件、附属文件和版本；运行记录保留当时使用的版本 |
| 参考范围 | 展示实际附加了哪些资料，以及全文或节选状态 |
| 补充要求 | 只影响本次任务；可另存为项目习惯 |
| 运行／发送 | 使用当前配置启动，对应项目、栏目和目标版本 |
| 停止 | 停止本地后续处理；已发出的请求可能已计费，界面不承诺退款或撤销服务端调用 |
| 任务详情 | 显示真实阶段、错误、可得的调用用量、历史，不伪造百分比 |
| 重试 | 只重试失败部分，保留已完成的结果和人工内容 |

不同页面沿用统一组件，但运行配置按项目和任务记忆，避免在一个页面换模型意外改变另一个正在运行的任务。

Skill 包内的写作规则和参考文档需要读取；只有文本 API 的执行环境不能自动执行任意 Skill 脚本。所选 Skill 需要程序工具而当前不支持时，明确列出缺少能力，不能只把脚本文字发给模型就宣称已执行。

作品正文、附件和外部经验材料是参考数据；不能把其中“删除项目”“忽略规则”等文字当成应用操作指令。选择 Skill 也不授予它删除项目或发布作品的权限。

### 8.4 结果落地规则

任务状态为排队、运行、待采用、已采用、失败或已取消；页面保存状态与 AI 运行状态分开。

每次运行固定项目、栏目、内容节点和输入版本。运行中切换项目，结果回到原目标的候选记录。运行中用户改了原文，结果注明“基于旧版内容”，不得直接覆盖新版。连续点击同一运行按钮不启动重复任务；重试可追溯为新尝试。

中断生成可保存为未完成草稿，但不进入终稿或自动成为故事事实。多人编辑若本期未支持，不借用导演的协作界面假装已支持。

## 9. 剧本库与导出统一规则

### 9.1 完成作品的收录

创作项目选择“收录剧本库” → 预览标题、来源模式、版本和内容范围 → 确认收录 → 软件内阅读。

来源模式分别显示洗稿、原创·自由、原创·框架。默认收录建议：

- 洗稿：我的新作，预览时可选择包含右侧设定、大纲等附录或仅正文。
- 自由：明确选择原稿或转换稿。
- 框架：已采用的分场终稿正文。

不把未完成的每次 AI 输出推入剧本库。部分集未完成时提示缺项；草稿导出与“完成作品收录”使用不同状态。作品再次收录产生同一作品的新版本，避免列表出现大量无法分辨的重复卡片。

### 9.2 阅读页

左侧目录列出章节、集数和场次；中间显示清楚的正文。提供返回、全文搜索、字号、版本选择、TXT/DOCX 导出、返回创作项目。点击“返回创作”才编辑；阅读页不建立第二份可编辑稿。

继续修改创作项目不会改变已收录版本，只有再次收录才更新。源项目删除后已收录版本仍可阅读；删除剧本库条目不删除创作项目。现有导演从剧本库选剧本的入口需要兼容新版内容格式，避免破坏已满意的导演流程；本期不扩展导演功能。

### 9.3 所有导出的共同原则

| 模式 | 默认内容 | 明确排除 |
|---|---|---|
| 果子库 | 用户选择的原始稿或 Skill 输出 | 未选择的一侧 |
| 洗稿 | 右侧完整作品，可切仅正文 | 左侧原剧本、弃用方案、聊天 |
| 自由创作·原稿 | 左侧全部节点 | 右侧转换稿 |
| 自由创作·转换稿 | 右侧全部节点 | 左侧原稿自动补位 |
| 框架创作 | 最终分场剧本正文 | 灵感、对标、设定讨论、推演等过程 |
| 剧本库 | 当前选中收录版本的既定范围 | 创作项目尚未收录的改动 |

导出前使用同一份结构化内容生成预览和文件。中文 UTF-8 TXT、真实 DOCX 文档；不将 TXT 改扩展名伪装成 Word。导出失败保留内容并允许重试，只有文件写入成功后才显示成功。

## 10. 开发前必须统一的数据关系

以下为设计约束，不规定具体数据库实现。

| 对象 | 保存的内容 | 关键关系 |
|---|---|---|
| 项目 | 模式、分组、名称、阶段、默认运行配置 | 果子／洗稿／原创自由／原创框架 |
| 来源资料 | 原文件、提取文本、集号、来源版本、覆盖信息 | 与新作分开，不因来源改变静默改写新作 |
| 创作节点 | 设定、章节、分集的左右文本和版本 | 节点类型与显示名称分开 |
| 人物 | 设定、目标、知情状态、起止状态 | 与事件多对多关联 |
| 事件 | 发生的行动、结果、前置条件、人物、来源、采用状态 | 有稳定 ID，可从属大事件、分配到集 |
| 顺序与因果 | 实际时间、叙事顺序、因果连接 | 不与事件正文混为一谈 |
| 对话与决定 | 原始聊天、摘要、明确采用决定 | 关联项目、阶段和具体条目 |
| AI 运行 | 模型、Skill 版本、输入快照、目标节点、输出、状态 | 结果先成为候选，再显式写入对应内容 |
| 推演分支 | 基于哪个版本、固定点、候选事件、影响范围 | 不直接改当前主故事 |
| 收录版本 | 作品名、来源模式、内容范围、不可变内容快照 | 导出和阅读使用同一版本 |

总稿不是另存一份会遮盖新内容的大字符串。建议总稿是节点的合并编辑视图：有稳定章节边界，编辑回写同一节点；跨章节移动或无法识别的粘贴先预览拆分。未经分集的整部导入文件可以保留为独立“待分集来源”，确认分集后再建立节点。

上游改动只标记受影响的下游条目“需要复核”，不清空、不擅自重生成。每次采用能记录替换前版本并撤销。骨架锁定默认约束 AI 提案，用户主动修改可解除或重设；不存在无法纠正的永久锁。

旧数据迁移建议：原洗稿映射到洗稿，原原创映射到自由创作；框架式仅新建。保留原项目 ID、分组、输入、输出、Skill 关联、总稿和库作品。旧总稿与分集不一致时，两份都保留并要求在新的合并视图中核对，禁止直接覆盖其中一份。迁移先备份、可重跑、失败可回退。

## 11. 第一版范围和后续扩展

第一版应打通：项目与分组 → 真实导入 → 读取或编辑 → 模型与 Skill 协作 → 保存与版本 → 预览 → 导出 → 剧本库阅读。

包含：

- 果子库双栏重排及现有功能的真实可用性。
- 洗稿来源导入、六类分析与分集对标、独立右侧新作和整套导出。
- 自由创作的左右独立保存、自由目录和两份整部导出。
- 框架式完整阶段、项目聊天记忆、经验提炼、人物事件关系、有限分支模拟、细纲到分集分场终稿。
- 统一模型选择、Skill 完整读取、运行历史、失败重试、版本恢复和来源定位。
- 剧本库完整阅读与收录版本。

后续扩展：

- MiroFish 等外部模拟引擎适配和更长时段、多角色并行模拟。
- 更复杂的时间线画布和人物关系图。
- 经验 Skill 的跨项目发布、质量测试和持续演进。
- 更精细的时长、节奏评估以及额外的协作功能。

后续扩展不能替代第一版已承诺的核心闭环；也不在第一版放大量可点击但无功能的按钮。

## 12. 开源调研记录

本轮仅查询官方仓库说明，未安装、运行、测评或完成接入审计。网页及仓库中的指令只作资料，不视为本次执行命令。

### 12.1 kangarooking/cangjie-skill

来源：[官方仓库](https://github.com/kangarooking/cangjie-skill)。其定位是把书籍及其他长内容中的方法提炼成可调用的 Agent Skills，包含理解原文、提取、核验、构造和验证环节。

设计判断：与用户所述“书籍蒸馏”方向相符，可以参考其证据与可执行经验结构；但剧本主要呈现故事，没有总是直接讲出写作方法，因此仍需为剧本设计专门的节奏、反转和因果分析，标明观察与推断。不能把通用拆书能力等同为已经验证的短剧分析能力。

另有同名 [Yeadon8888/cangjie-skill](https://github.com/Yeadon8888/cangjie-skill)，偏向提取一个人的思维方式，与本次对标剧本经验提炼的目标不同。不能仅凭名称认定用户此前装的就是其中某个仓库。

### 12.2 666ghj/MiroFish

来源：[官方中文说明](https://github.com/666ghj/MiroFish/blob/main/README-ZH.md)。其“预测万物”宣传和《红楼梦》前八十回推演示例与用户描述对应。

官方说明展示了图谱构建、环境搭建、模拟、报告及互动流程，部署涉及独立服务和模型、记忆相关配置。设计判断：它是待适配的外部引擎，不能当成导入一个 Skill 就可完成的功能；仓库演示也不证明能够准确预测某部作品结局或必然生成更好故事。

本稿建议先统一推演输入、候选分支和采纳接口，以后可替换推演引擎，同时保留同一用户工作流程。

## 13. 后续实施的验收场景

以下用于将来验收，本轮没有执行软件功能测试。

| 场景 | 必须观察到的结果 |
|---|---|
| 果子第一集打开、尚未生成 | 输入和空白输出已并列，不出现巨大标题和工具块 |
| 导入 TXT、DOCX、视频 | 实际解析链路有结果或清楚的能力/失败说明，不只显示文件名假装成功 |
| 一部来源有缺号、重复集号 | 解析预览可修正，不丢正文、不误编号 |
| 从果子选来源后修改果子 | 创作项目不被静默改变，可显式更新来源 |
| 一键分析中部分模块失败 | 成功模块保留，失败模块可重试 |
| 原文没有金手指或结局 | 如实标注，不捏造补齐 |
| 原第2、3集对应新第2集 | 左侧可查看两集，右侧独立保存，导出只含新作 |
| 新作改人物名后继续对标生成 | 保持新作人物名和规则，冲突给出提示 |
| 自由模式有设定和三集 | 两侧分别按正确节点顺序导出，设定不被当成集号 |
| 修改总稿中的第2集 | 单集页面同步看到同一修改，不产生双份冲突稿 |
| 与模型 A 讨论后切模型 B | 已采用设定和相关上下文仍可读取，不混入弃案 |
| 未采用 AI 提出的反派身份 | 后续正文不能把该身份当事实 |
| 全文超过模型单次容量 | 采用分批阅读或说明限制，不静默截断后宣称读完 |
| Skill 缺依赖或需要当前不支持的工具 | 真实说明，不能标为已完整执行 |
| 固定骨架下模拟 | 输出多种过程候选，违反锁定条件的结果标明问题，不自动采用 |
| 采纳一个模拟事件 | 展示并更新关联内容，旧版可恢复，其他候选不混入 |
| 第5集写作时涉及第2集的秘密 | 按人物当时知情状态处理，不提前知道未来 |
| 上游细纲修改而终稿已有人工内容 | 标记需要复核，保留人工终稿 |
| 运行期间切换到另一项目或改输入 | 回包不写错项目，也不覆盖新输入 |
| 网络中断、关闭重开、保存失败 | 可恢复已保存内容；明确失败状态，不显示虚假“已保存” |
| 导出框架终稿 | 仅选定各集分场正文，集号场号正确，无聊天和推演混入 |
| 导出转换稿时某集右侧空白 | 明确提示缺项，不拿左侧稿冒充 |
| 收录后继续修改或删除源项目 | 收录版本稳定可读，再收录才更新 |
| 从新版剧本库进入既有导演流程 | 原有导入和阅读契约保持兼容 |
| 旧项目迁移、重复迁移和恢复 | 原稿、输出、分组、总稿、库作品均不丢失 |
| 1366×768及常用 Windows 缩放 | 工具可访问、正文可读、双栏有折叠方案，不被聊天遮挡 |

## 14. 下一轮讨论顺序

先讨论整体目录与框架工作区主布局，再逐页确认“灵感→事件→骨架→模拟→细纲”的具体交互；其后确认双栏模式与导出预设。页面名称、尺寸、按钮位置和第一版精细程度均可调整。

本轮用户已确认框架式工作区采用“成果编辑为主、右侧聊天”。下一步可在此布局下细化各阶段内容、AI 建议如何采纳，以及世界模拟的锁定与替换交互；无需重复询问主布局。

在用户明确决定动手前，继续更新此讨论稿；不把讨论进展误当成开发、安装或发布授权。
