# 人物语音贯通制作流程

用户要求：项目协作（第二张截图）新增语音页，卡片沿用美术布局。信息读取逐集识别普通对白人物；主要人物按实际出场的不同集数 >=3 统计，旁白、画外音、心声不计讲话。全剧读完汇总人物并收录一条原著对白。卡片显示人物美术描述、原话、语音模型、音色描述、生成结果、上传本地语音、试听、确认音色；确认后复用同一音频，重新生成不能悄悄替换已确认样音。

清单模型提取逐场正常对白并保留逐字原文证据，身份跨妆造复用，统计按集去重。旧项目能只补读语音，不重做美术。未读完显示进度和暂定统计，不声称全剧已完成。脚本变更使相应提取失效。

关联：提示词全文判断实际说话的人，图片用途与讲话独立；人物出镜不等于说话。项目分镜、图视整本素材和自动化共享编译规则。无提示词时采用场景对白关联，出现提示词后按条细化。导入文件夹的音频同图片一起参加 AI 分发，无关素材不进入生成请求。确认音色保存人物、模型及音频身份；账号/项目隔离，晚到响应和历史版本不能覆盖新选择。

视频提交：保留原始完整关联，能力筛选仅作用于本次请求；不支持音频取0，5条支持3条则稳定取3条，遵守总参考数限制并重排 @audio 编号，去除被省略音频的引用。切换模型可恢复所有原始音频。客户端预览和主进程最终请求必须一致；既有图片人工选择、发布门禁和鉴权保持。

语音生成结果：结果进入本地语音生成目录和索引，生成后默认待保存；每条结果都可播放查看、导出 WAV、单独保存或删除，结果区提供一键清理全部。清理会同时移除索引中的历史结果和目录内遗留音频文件，避免旧结果继续显示；人物确认音色时，关联到已保存的生成结果，上传的本地音频也能作为人物音色。

方案：使用既有清单 checkpoint / 版本化关联与生成适配器扩展；不为每个页面创建独立音色数据，也不强制用户重做美术。音频文件先落本机，确认后可上传项目素材沿用现有协作服务；避免接口密钥写入项目数据。原有模型无音频能力时正常生成。

实现沿用 React/Electron/Node，无额外模型依赖。按现有 AGENTS 授权直接实现、独立复核、测试、界面验证、打包发布；真实收费视频使用模拟接口验收。

补充（2026-11-01）：信息读取对缺失或无效speakers自动补读并报告错误。确认样音独立复制到人物音色目录，结果清理不破坏固定音色。美术按集/场景/提示词导出均先选择是否包含对应音频，使用完整已确认关联，不受当前生成模型容量裁剪。
