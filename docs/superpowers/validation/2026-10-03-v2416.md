# 2.4.16 生成恢复、时长与视觉验证

## 需求

修复用户 2.4.15 整本生成的中断原因；最高时长支持 0～35（0 为自动判断、单条不超过35）；保留白底黑体、青色条号和绿色时长，选中项用纯淡紫色，风格/画幅使用独立按钮，加强卡片边界。

## 故障证据和处理

- 在只读的实际保存批次中核对 15 个失败场景。未标记动作被当成上一句讲话延续，导致错误的台词字数、时长和 D 行逐字比较；修复为已知人物+可观察动作规则，同时保护引号内的真实多行台词、未完句的无引号续行、称呼和原始 UTF-16 范围。对白和动作计时共用同一已解析讲话范围。
- 原文末尾独立 `-->` 被当作需覆盖正文。删除仅限独立、未在引号中的导入格式标记，保留原文快照并记录 sourceMap；不会改写剧本或删掉引用内的字符。
- 保留已通过的本地条目，模型修复回包的重复副本不再覆盖或阻断其他正确条目；最终核对使用本地保留的完整场景输出。
- v6 旧任务先验证完整台词、声源、镜号和分段容量。完整合法旧付费分区保持 ID 和已发布计划不变；确需调整计划时保留旧计划、旧卡片和原回包，新计划可复用精确相同原文范围的完整付费文本。
- 真实数据副本恢复结果：12 场、34 条草稿通过本地校验、保存与模拟最终核对，未新增 Skill 调用；22-2、23-2 需重新划分后的整场输出，24-1 已有旧分段计划可本地纠正但没有可用的已生成正文。三场均保留原历史，需要用户继续任务时调用生成接口。本轮未修改真实项目、任务和账号数据。
- 另一个旧批次全部212场遭 WorkBuddy 网关按 Key 的120次/60秒限制。安装版 `server/routers/gateway.py` 已确认在上游请求前拒绝并返回明确429，未计费。客户端同 Key 跨模型共享600ms入场间隔，最多100次/60秒，实际模型请求仍并行。只对该网关明确的前置限流拒绝等待完整窗口（或更长 Retry-After），最多两次重试；未知429、超时、部分付费输出及额度错误不重复付费调用。耗尽后批次保存并暂停。
- 发布前独立审查发现并修复四个边界缺陷：未完句续行保护；桌面 IPC 和 Skill 执行保留 `RATE_LIMITED` 分类；控制器移除 HTTP 502/503/504 盲重试；旧付费复用按全文 sourceMap 映射后的精确原文位置一对一匹配，避免重复原文拿到另一处的表演。

## 验证

- 新行为测试先红后绿：未标记动作、格式标记/引用保护、动作计时、旧D行精确修复、已通过条目保护、付费草稿恢复、限流暂停/历史记录。独立审查的新增用例先失败7项，再全部通过；并发付费回包保护用例先失败1项，再全部通过。完整 `npm test`：1105 pass、0 fail、13 suites。`npm run build` 成功。
- 执行实际 `main.cjs` 的 ai-chat IPC handler，经过 Skill 执行和真实批次控制器，验证明确限流能暂停整个任务且下一场保持 pending；结构化错误只传分类、消息和已付费正文，不复制接口秘密。HTTP 502/503/504 无论有无部分输出均只调用一次，明确完成截断仍保留现有一次增大输出额度的恢复规则。
- 并发2场时，一场限流耗尽仅请求其他场完成当前请求后暂停，不取消已转发的付费输出。测试分别覆盖其他场完整回包和截断 `partialText` 落盘，后续场保持 pending；继续时已完整回包仅需核对，零新 Skill 调用。账号或权限变化仍立即停止。
- 212场假时钟限流模拟：单 Key 窗口保持每分钟最多100次且请求重叠；取消排队/冷却、多模型共享额度、Retry-After及最多两次恢复均覆盖。
- 时长测试覆盖0和1～35、越界/非整数拒绝、正值建议时长、0与35快照区分、自动35上限、原30秒快节奏例外不变；请求、核对、保存与恢复均传递真实有效上限。
- 实际 Electron 隔离副本：切页后单场35、整本0分别保留；0明确显示自动估算最高35；单场和整本均有36个选项。
- 视觉计算样式：选中背景 `rgb(238,233,250)` 且 `backgroundImage:none`；风格/画幅按钮圆角999px、独立边框和间距。青色条号 `rgb(237,249,251)`，绿色时长 `rgb(230,245,239)`；剧本和提示词纯白，字体优先 Microsoft YaHei。
- 1600 / 1280px 双栏底部差小于1px；1024px自然上下分栏。三个尺寸均无页面横向溢出。截图、检查JSON和真实数据回放报告位于忽略目录 `output/playwright/v2416` 和 `qa/director-reliability`，不提交用户缓存/凭据。
