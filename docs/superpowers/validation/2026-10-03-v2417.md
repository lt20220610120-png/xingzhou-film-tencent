# 2.4.17 整场 Skill 提交、生成恢复与正文布局验证

## 需求与流程对照

用户明确自动分段只替代人工时长划分，划分后的完整场景交给原 video-prompt-fast-v8-2 Skill，一次预演、一次输出全部括号对应的提示词。任务状态展开应增加页面高度，不能挤占正文框。继续修复整本生成中断并发布更新。

此前实现已经整场调用一次 Skill，但自动模式额外提交了规划状态、拍法和程序提取的台词表。它们可能影响原 Skill 的导演判断，且错误台词解析会在生成与校验间反复传播。现在将时长划分规则提取到内置独立模块，人工与自动模式共用 buildWholeSceneSubmission；自动生成首轮只提交完整原文、全部括号、必要项目事实和建议时长，不再提交上述导演规划与台词表。仅继续已有任务时附只读的保存草稿及真实修复问题。没有括号的短场保持一条输出。

已完整阅读用户提供的 Skill 主文及 direction、lighting、output-contract、examples 参考；所选 Skill 的六个文件继续完整加载，未改写用户 Skill。原文声源、导演预演、同场光影、人物道具与镜头连续性由原 Skill 负责；本地仍校验原话、来源范围、完整数量和保存结果。

## 人工样本对照

只读项目「原来校花高冷反差」的实际工作记录与用户提供的完整提示词文档：30集、158条保存输出；文档对应158个编号。以生成时保存的 sourceText 对照104个场景，其中38场无括号、66场有括号，100场输出数量符合括号数或无括号一条。三个历史场景只有（2）标记、首段未标记但输出两条；另一个无括号场景历史输出两条，未将这些记录当作全部符合规范。

1-5厨房场无括号，输出一条含13个分镜的提示词；2-5、3-1各两个括号对应两条输出。这支持用户要求：镜头数不决定分段数量，完整场景先预演，括号只限定输出边界。不把用户私人全文或缓存提交到仓库，不针对这一本书硬编码切点。

## 实际中断原因与恢复

最新225场任务副本的六个失败场景：38-2、40-2、43-1包含未标记动作，被错误拼入上一句台词；39-1将「巴恩斯皱眉」错认成说话人并把动作当对白；41-1省略号后紧接人物对白未被识别；41-2整场紧凑单行文本被标题清理吞掉，导致正文为空及容量错误。并非全部由时长切点造成。

- 台词解析使用已知人物和有边界的动作描述，保护引号内及真正未完句的多行讲话，保留OS/VO与原文位置。
- 紧凑标题只移除标题前缀，保留同一行人物名单、动作和对白；原始UTF-16位置映射继续有效。
- 处理版本升级为8。恢复先选择已有可通过校验的完整付费回包，保留已保存条目，拒绝用错误修复副本覆盖；仅确切已发布且仍合法的旧付费分区保留非尾段时长偏好例外，不放松句子、容量和原文完整性要求。
- 只读复制任务回放：38-2恢复4条、39-1恢复5条、40-2恢复2条、41-1恢复6条、43-1恢复3条，共20条；计划与付费条目ID保持不变，保存文本哈希一致，均只调用模拟整场核对。41-2没有可用已生成回包，模拟接口明确阻止新规划调用；更新后继续任务才会重新请求该场。没有修改真实用户项目、任务或账号数据，未重新批量付费生成。
