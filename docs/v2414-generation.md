# v2.4.14 整场生成与恢复

软件先按原文和最高时长划分完整场景，再把所有 `（1）…（N）` 正文一次提交给所选完整 Skill。Skill 先预演整场、统一角色/道具/伤势/光源和相邻镜头，再一次输出全部提示词。原始 Skill 主文件与五个附件保持不变；不再逐括号调用 Skill。

## 已确认的失败原因

只读复查用户第 4 集 4-5 的旧失败任务，发现 `系统 VO：发现魔教头目马库斯。主线任务：七日内拔除魔窟。` 中的“主线任务”被旧台词解析器当成新演员。实际已付费草稿包含全部原字，却因为程序提取的预期台词漏掉字段名而误报台词改变。新解析器将任务、奖励、条件、状态等字段标题保留在当前说话人的原话中，并继续允许甲、乙及未列在人物表中的真实小角色在句末换话。

修复后旧 4-5 第一条付费草稿通过本地严格校验，无须重生成或修改原台词。整场真实可听内容为 130 字、常速约 32.5 秒；符合用户授权的最高 30 秒、自然 30～35 秒整场紧凑合为一条规则。不是通过放宽“缺字/改字/重复”校验让失败稿过关。

OS、VO 和分镜声音行的格式修复仍只在台词原字、顺序和演员完全匹配时进行。数字原字、声源、台词正文和剧情不能借格式修复改写；光影基准变化也不能被豁免。

## 整场请求与回包

`buildWholeSceneSkillRequest` 包含完整括号正文、规范编号表、每条目标时长、原文连续台词表、状态/衔接计划与已有光影基准。30～35 秒自然估时压缩仍保留 `naturalEstimatedSeconds`，只用紧凑完整口播、动作同步与简洁切镜达到 30 秒目标。

输出预算按条数分配，最低 16384、最高 32768，与实际接口上限一致。预算不足时保留回包和错误；不会通过截掉原文或 Skill 附件来节省上下文。

整场完整回包先存入 `wholeSceneResponses`，然后按规范 ID 严格拆成卡片并逐条本地校验。规范集-场-条编号和旧括号编号均可识别；不能按数组顺序把错误、重复或缺失编号重新标成预期编号。已通过卡片即时保存到右侧，整场语义核对完成后保留原 ID 转为正式结果。

缺条或无效条触发有界整场修复：仍提交全部原文、全部规范编号与已有草稿，已通过 `preservedPrompts` 正文必须原样保留，不另外单条生成。整场光影基准保持一致。语义核对修复也按整场合同执行；有原文依据的问题最多修复两轮，后续提示保留明确核对提醒，不把本地台词/结构错误当成成功。

## 断点与旧任务

任务 `processingVersion` 为 6。完整回包已存盘而尚未拆包/校验时，重启直接消费缓存，不再调用 Skill。截断回包和同次有界重试使用同一个 `requestGroupId`：若完整重试正文已缓存，先跳过同请求链的旧截断稿，保留其历史，避免重启时误锁定旧半包文字并重复付费。

只有明确截断、仅推理/无正文和 429/502/503/504 才有一次自动接口重试；含糊超时和取消不会无限重发。整场质量修复也有固定次数，用户主动继续才进入新一轮。已付费原始回包、失败草稿、已通过正文和固定 ID 持久保存。

旧分区重新按完整讲话和自然时长规则审查。若分区边界/数量或整场压缩规则变化，保留旧计划、付费草稿、原始整场回包和正式历史，创建新的计划/片段/提示词 ID，不能用旧 ID 对应新的原文范围。分区不变时，优先本地重验旧稿，保留已发布计划不变。
