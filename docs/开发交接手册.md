# 行舟影视开发交接手册

开发工作区为 `D:/AI/Qwen3-TTS/xingzhou-release`。从[协作约定](../AGENTS.md)和[当前协作进度](Hermes协作进度.md)开始，核对 Git、`package.json`、公开 Release 和更新清单。独立发布工作区是本轮源码与打包入口。

桌面端是 Electron、React、Vite。受保护的项目、媒体和配置由主进程负责。preload 提供白名单接口 `window.xingzhou`。新增 IPC 要校验调用者、参数和路径。Node.js 云端 API 通过 PostgreSQL 持久化共享数据，并通过 COS 保存媒体，Nginx 提供 HTTPS 与反向代理。具体维护见[云端说明](../cloud-backend/README.md)和 [Win AI 说明](../win-ai/README.md)。

## 数据与行为约定

- 保持本地项目和云协作的保存边界。保留旧项目 ID、原稿、版本、任务和媒体引用，兼容旧草稿与旧快照。
- 先核对权限、幂等和冲突规则，再修改删除、恢复、覆盖、重试和生成链路。云端授权、许可和媒体读取边界由服务端及主进程实施。
- 协作中的旧请求、旧账号或旧版本回包不能覆盖当前编辑。使用保存检查点、版本号和稳定身份保证恢复。
- 分镜素材以资产卡 ID 保存关联，预览与提交读取当前采用图。正式生成使用已确认的输入，并保留未知提交状态供核对。自动化继续只补未完成项。
- 测试优先用项目副本、临时用户目录、隔离数据库与模拟生成接口。记录涉及的公网读取、云部署和真实数据操作。
- 遵循[前端与产品约定](../AGENTS.md)。页面改动验证 Electron 中的真实操作，涉及上传、下载和更新时验证主进程请求与恢复。

## 本地验证与正式发布

从发布工作区运行 `npm ci`、`npm test`、`npm run build`。根测试脚本聚合 core、Electron、云端及相关模块回归。与发布有关的 Python 测试可运行 `python -m unittest discover -s scripts -p "test_release*.py"`。

1. 更新 `package.json`、锁文件及 `release-notes/<版本>.md`，完成全量回归、构建和界面验收。
2. 按 `npm run release` 的正式链路制作 NSIS 安装包，验证安装包运行时。若该安装包已制作并验证，使用 `python scripts/publish_release.py` 发布对应工件。续发时核对同版本文件大小和 SHA-256。
3. 核对 GitHub Release、官网与两个 GitHub 默认分支的签名更新清单、公开安装包及软件内更新。使用 `node scripts/verify-public-release.cjs <current.exe> [previous.exe]` 核对三份签名清单、GitHub 摘要和官网范围响应。提供上版安装包时，另运行真实 Electron 更新验证。中断后先确认渠道和资产状态，再续发。
4. 更新[协作进度](Hermes协作进度.md)、本次 `docs/release-verification-<版本>.md` 及上级工作区 `软件更新记忆.md`。交付时附公开下载与现有本机安装包链接。

云端改动单独核对部署目标、迁移、现有备份、回滚与健康检查；真实密钥保存在服务器或安全存储。
