# 软件月卡管理（2.8.67）

现有三个账号 `xingzhou510`、`xingzhou123`、`staff002` 已按固定账号 ID 豁免。管理员与两位老用户继续用原账号；重装、换机、更新不需要卡密，也不会看到卡密界面或授权提示。新账号每次启动联网校验，只有有效月卡才能进入软件；到期停在授权页，不显示工作区。

## 给新用户发卡

1. 管理后台 → 软件授权 / 卡密，填写备注，生成一张月卡。
2. 立即复制或导出完整卡密，再发给用户。服务器仅存摘要，切页后无法再次显示明文。遗漏保存的未用卡先作废，再补发。
3. 新用户启动联网，输入月卡预验；然后自行注册或登录，完成时才兑换、绑定电脑并开始计时。注册仍需原有邮箱验证码和身份邀请码；卡密不授予角色或管理员权限。有效月卡启动页可提前续卡，续卡顺延剩余时间。
4. 激活后保留设备凭据，后续启动自动联网验证，无需重复输入已用卡；到期输入新卡。关闭预验窗口不会消耗卡，15 分钟后重新预验即可。

每张卡从首次完成激活时按北京时间对应日计一个月；月底不足取下月月末，例如 1 月 31 日至 2 月 28 日。提前续卡从原到期时刻继续加一个月；已到期则从本次兑换时刻开始。每次顺延都以上一到期时刻的对应日计算。

年度订单用于关联用户和第 1—12 月卡，每月生成并发一张。没有自动全年授权或自动按年续期。年度中断、退款等尚未确认，不自动处理。丢失未用卡可作废并补发同一订单月份；已兑换卡不能再作废，应在对应授权处理异常。

## 换机与异常

一份月卡授权同时绑定一台电脑。管理员在对应账号点“后台解绑”，填写原因并确认；用户在新电脑通过授权页的“恢复已购授权”受限登录，服务端验证后绑定新设备，剩余期限不变。恢复完成前始终不能进入工作区。原设备不再有有效使用授权，但可凭原设备证明和有效账号会话查询已有任务、下载与导出资料；不能新收费或修改云端项目。撤销和恢复同样记录审计。

系统设备密钥损坏属于售后：关闭软件，先后台解绑，再备份并移走用户数据目录中的 `software-device-key.json`，重开后用原账号恢复；保留其他项目、会话与数据文件。设备私钥由 Windows safeStorage/DPAPI 保护；本版未接 TPM，不能承诺绝对不可复制或防改包。

启动必须联网，无离线宽限。运行中每 60 秒校验，收费提交前再次检查。故障、到期或撤销后隐藏并锁定工作区，已保存资料和后台已有任务继续保留；授权恢复后正常使用。旧账号按服务器豁免直接进入原界面，不经过卡密门禁。

## 更新与运维

更新入口位于启动授权页，设置只显示当前版本。未激活、已到期也能下载官方更新，更新不延长授权。签名清单、可信下载源、大小与哈希校验保持原机制。

旧客户端只允许三个豁免账号继续走原协议；非豁免账号必须提供一次性设备挑战签名和新协议字段。版本号上报不是防篡改证明。云端检查保护云端服务与官方客户端流程，不能保证阻止逆向改包复用用户自带 API 的纯本地能力。

部署脚本 `scripts/deploy-software-license.py` 校验旧服务器文件摘要及三个账号 ID/用户名，用 PostgreSQL 所有者执行增量事务，并只授予应用账号新表 CRUD 与审计序列权限。脚本固定保护本次旧基线，后续版本须更新预检摘要，不能盲目重复执行。部署前备份源文件与 drop-in，失败恢复旧服务；增量表保留用于排查，不删除用户数据。旧的 `tencent-threat-model.md` 不是本功能最终规格。
