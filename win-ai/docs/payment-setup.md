# Win AI 收款配置

2026-10-18：用户将支付纳入当前范围。示例 maxforai.top 的公开状态接口可读，但充值接口要求登录，后续用户截图已确认“站内 /epay/submit.php → cashier.haozpay.com 收银台”的实际页面链路。未获得该收银台的正式接口文档或商户资料，不能把收银台地址直接当作可用网关接口。**界面相同不代表收款服务商相同。** 当前沿用同一 New API 模板的原生钱包、充值、订单、套餐、兑换码和账单设置；没有填入示例站或虚构的商户数据。

## 第一步：确认实际支付渠道

用户截图已确认支付宝/微信、10/20/50/100/200/500、自定义金额、付款确认、订单二维码、约10分钟有效期与支付状态检测。本站沿用原生钱包与这些金额档位。截图中的外部收银台是 cashier.haozpay.com；需要其运营主体提供实际商户开通、接口文档及回调规范，不能仅凭域名推定协议兼容或平台资质。商品与真实 API 服务一致，不复制“日用品/服装”等不符商品描述。

Win AI 管理后台：`https://winai.xingzhoufilm.cn/system-settings/billing`。使用本机 `打开WinAI管理后台.cmd` 登录，进入“计费设置”中的“支付设置”。管理员账号与用户的行舟账号分开；行舟管理员不会自动获得 Win AI 站长权限。

## 第二步：接入自己的商户

若渠道提供易支付兼容接口，在其商户后台找到并填入：

| Win AI 设置 | 填写内容 |
| --- | --- |
| 支付地址 PayAddress | 你自己的支付服务商网关 HTTPS 地址，不能填写示例站地址 |
| 商户 ID EpayId | 支付服务商给你的商户编号 |
| 商户密钥 EpayKey | 直接在 Win AI 管理后台填写，不发到聊天或源码中 |
| 支付方式 PayMethods | 仅启用商户实际开通的渠道，例如 `alipay`、`wxpay` |
| 最低充值 MinTopUp | 你确定的最低充值额度 |
| 单位价格 Price | 每单位站内额度的收费；先核对币种、显示汇率和模型售价 |

易支付到账通知地址：`https://winai.xingzhoufilm.cn/api/user/epay/notify`。原生订单会自动带此地址；如果商户后台要求另填通知地址，也填写这里。付款后返回页面不能作为到账凭证，必须收到可信支付回调。交易状态、签名与订单由网关处理；重复回调只入账一次。

若确定使用 Stripe：填写自己的 Secret Key、Webhook Secret、Price ID 等对应设置；回调路径由对应支付设置说明提供。Creem/Waffo 等同理。只配置实际开通的渠道，不要混用不同平台的 ID 与密钥。

## 第三步：普通收款码或跳转链接

普通微信/支付宝个人收款码不能直接替代 EpayKey，也不能证明某个网站订单已经支付。单纯上传二维码不会自动充值。

只有收款码时，先在商户平台开通能返回订单查询/回调的接口，再接自动充值；或者采用明确标注“人工核实到账”的流程。当前已准备原生“额外充值链接”及管理员额度/兑换码工具，可作为人工处理入口，但**不把二维码展示等同于自动对账订单系统**。未提供收款码、链接或商户资料，因此本次没有发布任何可收款二维码，也没有开放人工支付订单。

## 第四步：站长本人确认模板声明

固定 New API 版本要求站长阅读并确认其运营与收费声明，才允许启用支付。声明涉及你实际拥有的上游授权和运营责任，需要你在支付设置中阅读并按实际情况确认；部署程序不会替你作事实承诺。未确认或商户未配置时，用户钱包不可真实付款。

## 第五步：验证与开通

1. 保存设置，打开普通行舟用户的 Win AI 钱包，核对显示金额、币种、付款方式与收款主体。
2. 先做商户沙箱验证：未支付/失败不加款，错误签名与金额不符拒绝，重复通知不重复加款。
3. 商户沙箱通过后，由你本人做一笔小额真实付款，核对商户到账、站内订单和额度三者一致，再向用户开放。此处尚未进行真实付款。
4. 接入上游并设置模型价格、分组倍率及令牌限额；余额充值与模型售价是不同设置，不直接复制示例站价格当作利润保证。
