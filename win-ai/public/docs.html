WIN AI / API DOCUMENTATION

连接 Win AI。

v0.1.0

应用只需要填写 Win AI 的接入地址与令牌。上游密钥、路由和模型映射由管理员在服务器端管理。

首版暂不开放在线充值和自助注册，由管理员分配测试账号。上游尚未配置时没有可调用模型；文档中的模型编号是占位符。

快速开始

在支持自定义 API 的客户端中，填写以下信息：

https://winai.xingzhoufilm.cn/v1
  • API Key：在 Win AI 控制台创建的令牌。不要填写上游网站的密钥。
  • 模型：使用令牌允许访问的实际模型 ID，不使用网页显示名。
  • 路径：SDK 的 Base URL 包含 /v1；如果工具会自动追加 /v1，只填写站点根地址，避免重复。

01 / 获取 API 令牌

使用管理员分配的账号登录，打开 API 令牌 →，创建一个专用于当前应用的令牌。按需要设置可用模型、分组和额度，复制后妥善保存。

请求使用 Authorization: Bearer YOUR_WIN_AI_KEY。密钥应放在环境变量或应用的密钥设置中，不应写入公开网页代码或源码仓库。

02 / 查看可用模型

模型列表由当前令牌和管理员已启用的上游决定。以下请求只读取列表：

export WIN_AI_BASE_URL="https://winai.xingzhoufilm.cn/v1"
export WIN_AI_API_KEY="YOUR_WIN_AI_KEY"

curl "$WIN_AI_BASE_URL/models" \
  -H "Authorization: Bearer $WIN_AI_API_KEY"

将返回的 data[].id 用作后续请求的 model。列表为空时请联系管理员配置渠道与授权，不要把示例模型当作已上线模型。

03 / 发起一次对话

先设置环境变量，并将 YOUR_MODEL_ID 替换为上一节返回的模型 ID。此请求会调用模型；用量以控制台日志为准。

curl "https://winai.xingzhoufilm.cn/v1/chat/completions" \
  -H "Authorization: Bearer $WIN_AI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_MODEL_ID",
    "messages": [{"role": "user", "content": "你好，请介绍一下你自己。"}],
    "stream": false
  }'
# 先安装依赖：pip install openai
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["WIN_AI_API_KEY"],
    base_url="https://winai.xingzhoufilm.cn/v1",
)
result = client.chat.completions.create(
    model="YOUR_MODEL_ID",
    messages=[{"role": "user", "content": "你好，请介绍一下你自己。"}],
)
print(result.choices[0].message.content)
// Node.js 服务端环境；不要在公开网页中暴露密钥。
const response = await fetch(
  "https://winai.xingzhoufilm.cn/v1/chat/completions",
  {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${process.env.WIN_AI_API_KEY}`,
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      model: "YOUR_MODEL_ID",
      messages: [{role: "user", content: "你好，请介绍一下你自己。"}]
    })
  }
);
if (!response.ok) throw new Error(`请求失败：${response.status}`);
console.log(await response.json());

流式对话可设置 stream: true，客户端需要按 SSE 协议读取。上游需要支持相应接口与流式能力。

接口路径

以下是网关支持的常见协议入口，并不代表所有上游或所有模型都支持这些能力。

用途路径条件
模型列表GET /v1/models需要有效令牌
对话POST /v1/chat/completions对话渠道
ResponsesPOST /v1/responses渠道支持 Responses
Claude MessagesPOST /v1/messages对应协议及鉴权头
图片生成POST /v1/images/generations已配置图片模型
图片编辑POST /v1/images/edits上游支持编辑
视频任务POST /v1/videos已安装并配置对应视频渠道/适配

图片、视频与多模态的参数、文件上传、任务查询协议可能因上游而不同。管理员应先核对对应渠道支持情况，再提供该模型的调用说明。任务超时后优先查询原任务，避免重复提交。

常见错误

情况检查方法
401 / 403检查令牌、Authorization 格式、IP 与模型权限。
额度不足联系管理员分配测试额度；首版没有在线充值。
无可用渠道 / 模型不存在核对模型 ID、分组、渠道启用状态与上游权限。
429达到并发或频率限制，降低并发并稍后重试。
上游错误 / 超时查看调用日志并联系管理员；不要连续重复创建付费任务。

管理员 / 接入自己的上游

  1. 在 渠道管理 → 创建渠道，选择匹配的接口类型。
  2. 填写上游提供的 Base URL 和 API Key，而不是该网站的控制台或文档网址。
  3. 拉取或填写上游实际支持的模型 ID，设置用户分组；模型别名使用模型映射。
  4. 保存后先做必要的测试，再给测试用户分配账号、额度和令牌。
其他中转站只要提供受支持的兼容 API，也可以成为上游。只有网页、没有可用 API 的网站无法直接接入；私有图片/视频协议需要单独适配。

自定义价格、支付商户与充值流程留到后续。首版不预设利润、不绑定支付服务。

行舟影视 / 接入方式

现阶段可在行舟影视现有的自定义 API 设置中填写本站地址、Win AI 令牌和已开放的模型。不同生成能力使用其对应的配置项。

专属 Win AI 栏目属于后续客户端集成。本次只部署独立网站，未修改或发布行舟影视客户端，也不会自动导入软件里已有的第三方密钥。
